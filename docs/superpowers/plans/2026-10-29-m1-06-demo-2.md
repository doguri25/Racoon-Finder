# M1-06 데모 2판 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** M1-05 데모(듀얼 패널, 파일 작업, PICK, 끌어서 이동)를 M1 Alpha 쪽으로 넓힌다. 단축키를 PRD KEY-01 원칙대로 OS별로 확정하고, 레이아웃 전환, 탭·주소창 고급 기능, 보기 모드와 열, 선택 도구, 빠른 보기와 미리보기 패널, OS와 호환되는 클립보드, 속성·체크섬, 연결 프로그램·터미널 열기, 작업 완료 보고·OS 알림·트레이를 더한다. 사용자가 자기 PC에서 내려받아 쓰는 데모(버전 0.2.0)로 낸다.

**Architecture:** M1-05의 구조를 그대로 쓴다. 순수 상태는 `crates/rf-ui/src/state/*`(Effect를 돌려주는 `AppState`), Slint 연결은 `controller.rs`, 문구는 `words.rs`, 화면은 `ui/*.slint`. OS 기능(클립보드 파일 형식, 연결 프로그램 대화상자, 터미널, OS 속성 창, 알림)은 `rf-platform`에 플랫폼별 모듈로 두고 rf-ui는 그 함수만 부른다. 해시·미리보기 디코딩처럼 무거운 일은 작업 스레드에서 세대 번호를 붙여 돌린다.

**Tech Stack:** M1-05와 같음 + `image`(png/jpeg/gif/webp/bmp/ico/tiff 디코딩), `encoding_rs`·`chardetng`(텍스트 인코딩 감지), `md-5`·`sha1`·`sha2`·`blake3`·`xxhash-rust`(체크섬), `notify-rust`(OS 알림), windows-rs(Windows 클립보드·셸 대화상자, rf-platform 안), objc2 계열(macOS 대지·NSWorkspace, rf-platform 안). 모두 `cargo add`로 추가하고 `cargo deny`가 통과해야 한다.

**Spec:** docs/PRD.md — KEY-01~03, LAY-01~03·06, NAV-01·03·06~08·10·11·13·15, VIEW-01·02(일부), DND-10·11, OPS-04·06·07·10·11, XFER-14·15.

## 이전 계획에서 이어받는 것

- M1-05 계획(`docs/superpowers/plans/2026-10-29-m1-05-demo-ui-shell.md`)의 Global Constraints와 화면 사양을 모두 따른다(UI 스레드 규칙, 세대 번호, 파일 변경은 작업 엔진으로, 문구는 words.rs와 .slint, 제품 이름 철자 금지, 스크린샷 확인, 자원 제한, `CARGO_INCREMENTAL=0`).
- M1-05에서 확인된 사실: Slint 1.18.1은 IME 조합 중 글자를 `text`에 넣지 않으므로 모든 새 입력란은 `composing` 가드를 쓴다. macOS에서 Home/End는 텍스트 커서를 옮기지 않으므로 테스트는 화살표를 쓴다. CI는 Windows·macOS 테스트를 실제로 돌리므로 테스트는 OS 독립적으로 쓴다(rf-ui 테스트의 OS별 경로 도우미, 임시 경로 길이 가정 금지, TOML은 `toml_string()`).
- 자동 배치된 커서는 파일을 바꾸는 명령의 대상이 아니다(`user_cursor()` 규칙). 새 명령도 이 규칙을 따른다.

## Global Constraints (이 계획의 추가분)

- **OS 코드 위치:** Win32·AppKit 호출은 `rf-platform`의 `#[cfg(target_os = "windows")]`/`#[cfg(target_os = "macos")]` 모듈에만 둔다. `unsafe`가 필요한 모듈은 첫 줄 `#![allow(unsafe_code, reason = "…")]`와 블록마다 `// SAFETY:`. Linux에서는 같은 함수가 동작하거나 `ErrorKind::Unsupported`를 돌려준다(Linux는 개발용). rf-ui는 cfg 분기를 하지 않는다.
- **OS 상호작용 테스트:** 순수 부분(CF_HDROP 버퍼 인코딩·디코딩, 경로 복사 문자열, 키 배정표, 인코딩 감지)은 모든 OS에서 도는 단위 테스트로 검증한다. 실제 OS 클립보드·알림·대화상자를 띄우는 테스트는 CI 러너에서 세션이 없을 수 있으므로 `#[ignore = "needs an interactive session"]`로 두고, 보고서에 손으로 돌린 방법을 적는다(테스트를 꺼서 녹색을 만드는 것이 아니라 대화형 세션이 필요한 검사를 분리하는 것이다).
- **단축키:** 모든 단축키는 `keys.rs`의 OS별 배정표 하나에서 나온다(Task 1). 다른 곳에서 키 문자열을 비교하지 않는다. 메뉴·툴팁에 단축키를 표기한다(KEY-03).
- **새 파일 쓰기 경로:** 클립보드 붙여넣기, 끌어다 놓기 외부 받기 등 파일을 바꾸는 모든 길은 여전히 `JobEngine`을 거친다.

## Review Focus

- 탐색기·Finder에서 복사한 파일을 이 앱에 붙여넣거나 반대로 할 때, 이동(잘라내기)과 복사가 OS 관례대로 구분되고 같은 이름은 `파일 (2).txt`로 붙는다(DND-10, DND-11). 잘라낸 원본은 붙여넣기 작업이 성공한 뒤에만 사라진다. (Task 8)
- macOS에서 Cmd+C 후 Cmd+Option+V는 이동이다. Cmd+V는 복사다. (Task 8)
- 큰 파일(수 GB)의 체크섬 계산, 큰 이미지·텍스트 미리보기는 창을 멈추지 않고 취소할 수 있다. 선택이 바뀌면 이전 미리보기·해시 결과는 버려진다. (Task 7, 9)
- 단축키 배정이 OS 기본과 겹치지 않는다: Windows F5는 새로 고침, macOS Enter는 이름 바꾸기, Cmd+Delete는 휴지통. 듀얼 패널 전용 동작은 OS 기본 조합과 겹치지 않는다. (Task 1)
- 한글 IME: 새로 생기는 모든 입력란(주소창 자동 완성, 패턴 선택, 체크섬 비교, 필터)에서 조합 중 Enter·Esc가 덜 된 글자를 확정·실행하지 않는다. (모든 UI 과제)

### Task 10: 연결 프로그램, 터미널, OS 속성 창 (OPS-04·06·11)

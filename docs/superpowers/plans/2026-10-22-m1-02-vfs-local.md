# M1-02 rf-platform과 rf-vfs 로컬 공급자 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** OS 기능(자연 정렬, 휴지통, 파일 ID, 숨김 속성, 알려진 폴더, 볼륨 정보, 덮어쓰지 않는 이름 바꾸기, 폴더 감시)을 담은 `rf-platform`과, 모든 공급자가 구현할 `Provider` 트레이트·`LocalProvider`·정렬·숨김 필터·공급자 적합성 검사 묶음을 담은 `rf-vfs`를 만들고, 10만 항목 폴더 목록의 기준 성능을 기록한다.

**Architecture:** `rf-platform`은 OS별 구현을 `cfg`로 나눈 자유 함수 모음이고, 워크스페이스의 FFI(`unsafe`)는 모두 이 크레이트에만 둔다. Linux는 제품 플랫폼이 아니므로 결정적인 대체 구현(자연 정렬)이나 `Unsupported`(휴지통)를 돌려준다. `rf-vfs`는 `unsafe` 없이 rf-platform 위에 블로킹·객체 안전 `Provider` 트레이트, `LocalProvider`, 감시 이벤트 병합, 정렬·필터를 올리고, 나중의 archive·remote·shell 공급자가 그대로 돌릴 적합성 검사 묶음(`testkit`)을 공개한다.

**Tech Stack:** Rust stable(edition 2024, MSRV 1.85), windows·windows-core(Windows), objc2·objc2-foundation(macOS), rustix(Unix), notify(macOS FSEvents, Linux inotify), dirs, bitflags, criterion·tempfile·proptest(개발 의존성).

**Spec:** docs/PRD.md (앞선 계획: `docs/superpowers/plans/2026-10-22-m1-01-workspace-core.md`)

## Global Constraints

- M1-01 계획의 Global Constraints 전부(언어·버전, 라이선스, `cargo add`로만 의존성 추가, 제품 이름은 `rf_core::identity`에만, `cfg` 규칙, `unsafe` 규칙, 커밋 메시지, 표준 검사, 교차 검사)를 그대로 따른다. 아래는 이 계획이 더하는 규칙이다.
- 새 크레이트는 `crates/rf-platform`, `crates/rf-vfs`다. 매니페스트는 rf-core와 같은 상속 블록(`version.workspace = true` … `publish.workspace = true`)과 `[lints] workspace = true`를 쓴다. 루트 파일, `deny.toml`, CI 파일은 고치지 않는다.
- FFI는 `rf-platform`에만 둔다. `rf-vfs`에는 `unsafe`가 한 줄도 없다. FFI가 있는 모듈은 첫 줄에 `#![allow(unsafe_code, reason = "…")]`를 두고 모든 `unsafe` 블록에 `// SAFETY:` 주석을 단다. objc2-foundation 0.3의 메서드는 안전 함수이므로 macOS 코드는 `unsafe` 없이 쓴다.
- Windows 경로 전달 규칙: 파일 API(std::fs, `GetFileInformationByHandleEx`용 열기, `MoveFileExW`, `ReadDirectoryChangesW`, `FindFirstFileExW`)에는 항상 `VPath::to_extended_length()`를, 셸 API(`SHCreateItemFromParsingName`)에는 `as_local()`을, 볼륨 루트 API(`GetDriveTypeW`, `GetVolumeInformationW`, `GetDiskFreeSpaceExW`)에는 `GetVolumePathNameW`로 구한 루트를 `rf_core::winpath::strip_extended_length`로 벗긴 값을 넘긴다. Win32에 넘기는 wide 문자열은 끝에 `0`을 붙인다.
- Windows 오류 변환: `std::io::Error::from(windows::core::Error)`를 쓰지 않는다. 이 변환은 HRESULT(예: `0x800700B7`)를 그대로 raw OS 오류로 넣어서 `ErrorKind`가 `Uncategorized`가 된다. 반드시 Task 2의 `win_util::to_io`를 쓴다.
- 모든 `Provider` 메서드는 블로킹이다. UI 스레드에서 부르지 않는다(PRD REL-03). `Provider`는 `Send + Sync + Debug`이고 객체 안전(`dyn Provider`)이다.
- 목록 묶음 크기는 2,000이다(PRD 8.3, `LIST_BATCH_SIZE`).
- 비로컬 `VPath`를 받은 rf-platform 함수와 `LocalProvider` 메서드는 아무것도 건드리지 않고 `Error::Unsupported`를 돌려준다.
- `rf_core::Error::io`의 `op` 이름은 다음 중 하나다: `"read_dir"`, `"stat"`, `"create_dir"`, `"create_file"`, `"rename"`, `"delete"`, `"trash"`, `"open_read"`, `"open_write"`, `"finish"`, `"file_identity"`, `"disk_space"`, `"volume_info"`, `"watch"`.
- 숫자 변환은 `From`, `try_from`, `to_ne_bytes`/`from_ne_bytes`로 한다(clippy pedantic `cast_*`). 1.86 이후 API(`cast_unsigned`, `io::ErrorKind::InvalidFilename` 등)는 쓰지 않는다(clippy `incompatible_msrv`가 막는다). 1.83에서 안정화된 `io::ErrorKind::{NotADirectory, CrossesDevices, DirectoryNotEmpty, StorageFull}`는 써도 된다. 문서 주석의 API 이름은 백틱으로 감싼다(`clippy::doc_markdown`). 긴 숫자 리터럴은 `_`로 끊는다.
- OS 비교 함수로 `slice::sort_by`·`sort_unstable_by`를 쓰지 않는다. 비교가 전순서가 아니면 Rust 1.81부터 정렬이 패닉할 수 있다. 정렬은 Task 12의 병합 정렬(`sort_entries`)만 쓴다.
- 실제 휴지통을 쓰는 테스트는 `rf_core::identity::TEMP_PREFIX`로 시작하는 고유 이름을 쓰고, 끝나면 휴지통에서 그 항목을 지운다.
- 성능 예산(공급자 몫 = PRD 목표의 50%, 나머지 50%는 뷰모델과 렌더링 몫): `list/1k_full` ≤ 25 ms(PERF-03 50 ms), `list/100k_first_batch` ≤ 250 ms(PERF-04 첫 화면 500 ms), `list/100k_full` + `sort/100k_name` ≤ 1,000 ms(PERF-04 전체 로드 2초). 판정은 PRD 7.1 기준 환경에서 잰 값으로만 한다.
- "실패를 확인한다" 단계에 적은 컴파일 오류 문구는 예시다. 아직 없는 항목을 가리키는 `error[E0425]`(함수), `E0432`(가져오기), `E0433`(타입), `E0583`(모듈 파일) 중 무엇이 먼저 나와도 되고, 테스트가 컴파일되지 않아 `test result` 줄이 없으면 실패가 확인된 것이다.
- 거의 모든 태스크에 `cfg` 코드가 있으므로 표준 검사 뒤에 교차 검사(두 타깃 clippy)를 늘 돌린다. Linux 컨테이너에서는 Windows·macOS 전용 테스트를 실행할 수 없다. 그 테스트의 "실패 확인"은 교차 clippy 컴파일로 대신하고, 실행은 Task 14의 CI가 맡는다.

## Review Focus

- 휴지통이 없는 위치(네트워크 공유, USB 메모리, Linux)나 휴지통이 받지 못하는 항목(260자를 넘는 Windows 경로)을 휴지통으로 보낼 때 → 영구 삭제로 바뀌지 않고 오류(`Unsupported` 등)가 나며 원본은 그대로 남는다(원칙 1, OPS-03). (Task 5 `linux_has_no_trash_and_keeps_the_file`, `long_path_is_never_deleted_permanently`, Task 15 단계 3)
- 대소문자만 바꾸는 이름 변경(`b.txt` → `B.TXT`)을 대소문자를 무시하는 볼륨(NTFS, APFS 기본)에서 할 때 → `AlreadyExists`로 막히지도, 파일을 잃지도 않고 이름만 바뀐다(OPS-02, REN-04). (Task 9 `check_rename`)
- 이미 있는 이름으로 이름을 바꿀 때 → 덮어쓰지 않고 `AlreadyExists`가 나며 두 파일의 내용이 그대로다(원칙 1). (Task 4 `refuses_to_replace_a_file`, `refuses_to_replace_a_directory`, Task 9 `check_rename`)
- 폴더 심볼릭 링크나 정션을 영구 삭제할 때 → 링크만 지우고 대상 폴더의 내용은 남는다. (Task 9 `permanent_delete_of_dir_symlink_keeps_target`)
- OS 자연 정렬 비교가 전순서를 지키지 않는 이름 조합을 정렬할 때 → 패닉하지 않고 결과는 입력의 순열이다. (Task 12 `stable_order_never_panics_on_inconsistent_cmp`)

## 이 계획이 일부러 다루지 않는 PRD 항목

- NAV-16 가상 위치(내 PC, 휴지통 보기·복원·비우기, 네트워크): shell 공급자와 rf-platform-win/mac 계획. 여기서는 알려진 폴더(`known_folder`)와 휴지통으로 보내기만 한다.
- OPS-12 휴지통 삭제 되돌리기: rf-jobs 계획(되돌리기 기록)과 rf-platform-win/mac(복원 API). 근거 자료는 `Deleted::Trashed { location }`이다.
- OPS-03의 확인창 문구, OPS-02의 입력 중 경고, NAV-11의 확장자 표시 토글, NAV-08의 열 클릭·2차 정렬 UI, NAV-13의 깜빡임·스크롤·선택 유지: rf-ui 계획. 이 계획은 `Capabilities::TRASH`, `SortSpec`, `WatchEvent`를 준다.
- NAV-07 "종류" 열의 셸 형식 이름 정렬: rf-platform-win/mac. 여기의 `SortKey::Kind`는 항목 종류와 확장자로 정렬한다.
- NAV-17 클라우드 상태 아이콘: M2. 여기서는 `Attributes::OFFLINE` 매핑까지만 한다.
- XFER-07(임시 이름 쓰기 → 원자적 이름 바꾸기) 절차, XFER-10 재개, XFER-11 메타데이터 보존(시각, 속성, ADS, xattr, 심볼릭 링크를 링크로 복사), XFER-12 대상 파일 시스템 제약 검사, COMP-02의 폴더별 대소문자 구분: rf-jobs 계획. rf-jobs는 `open_write`/`finish`/`rename(Replace)`/`delete(Permanent)`와 `VolumeInfo::fs_name`에서 시작하고, 필요한 메서드(`set_times`, `read_link` 등)를 `Provider`에 더한다.
- XFER-02 물리 디스크 판별, XFER-03 캐시 우회 I/O, XFER-05 빠른 경로(clonefile, 블록 복제, 서버 측 복사): rf-jobs(M2).

모듈 문서: "Natural (logical) filename order: the OS rule on Windows and macOS, a deterministic portable rule elsewhere." 이식용 규칙은 시그니처와 테스트만으로는 정해지지 않으므로 아래 정의를 그대로 쓴다. 이름은 `to_string_lossy()`로 읽고, ASCII 숫자가 이어진 구간마다 앞의 `0`을 모두 떼어 `Num(남은 길이, 남은 숫자)` 토큰 하나를 만든다. 그 밖의 글자는 `char::to_lowercase()`가 내는 글자마다 `Text` 토큰을 만든다. 두 이름은 `Vec<Token>`의 파생 `Ord`(사전식, 접두사가 먼저)로 비교한다. 이렇게 하면 전순서가 보장된다.

```rust
#[derive(Clone, Debug, PartialEq, Eq, PartialOrd, Ord)]
enum Token {
    Num(usize, String), // (digit count without leading zeros, digits): numeric value order
    Text(char),         // lowercased character; every Num sorts before every Text
}
```

- 그 밖: 키는 `Vec<Token>`, `compare`는 `Ord::cmp`.

```rust
pub trait Provider: Send + Sync + Debug {
    /// The scheme this provider serves; `Vfs` routes by it.
    fn scheme(&self) -> Scheme;
    /// What the location allows; errors yield `Capabilities::empty()`.
    fn capabilities(&self, path: &VPath) -> Capabilities;
    /// Streams the direct children of `dir` in batches of at most `LIST_BATCH_SIZE`
    /// (never empty); checks `cancel` at least between batches and then returns
    /// `Err(Error::Cancelled)`. Order is unspecified. An empty folder calls `sink` zero times.
    fn list(&self, dir: &VPath, cancel: &CancelToken, sink: &mut dyn FnMut(Vec<Entry>)) -> Result<()>;
    /// Metadata of `path` itself, without following a final symlink.
    fn stat(&self, path: &VPath) -> Result<Entry>;
    /// Creates one folder; `AlreadyExists` if anything is there, `NotFound` without a parent.
    fn create_dir(&self, path: &VPath) -> Result<()>;
    /// Creates one empty file with the same error rules as `create_dir`.
    fn create_file(&self, path: &VPath) -> Result<()>;
    /// Renames or moves inside one provider. `NoReplace` never overwrites; `Replace`
    /// atomically replaces an existing file. Moving a folder into itself is refused.
    fn rename(&self, from: &VPath, to: &VPath, mode: RenameMode) -> Result<()>;
    /// `Trash` never turns into a permanent delete; it fails instead. `Permanent` removes a
    /// folder tree, and for a symlink removes only the link.
    fn delete(&self, path: &VPath, mode: DeleteMode) -> Result<Deleted>;
    fn open_read(&self, path: &VPath) -> Result<Box<dyn ReadStream>>;
    /// The data is durable only after `WriteStream::finish` returns `Ok`.
    fn open_write(&self, path: &VPath, mode: WriteMode) -> Result<Box<dyn WriteStream>>;
    /// Space on the volume holding `path`; `None` when the provider cannot tell.
    fn space(&self, path: &VPath) -> Result<Option<DiskSpace>>;
    /// Starts watching `dir` (not its subfolders). `sink` runs on a background thread and
    /// is never called after the returned handle is dropped.
    fn watch(&self, dir: &VPath, sink: WatchSink) -> Result<WatchHandle>;
}
```

```rust
pub fn check_list_batches(p: &dyn Provider, root: &VPath) -> Vec<usize> {
    let d = fresh(p, root, "batches");
    let files = 2 * LIST_BATCH_SIZE + 500;
    for i in 0..files {
        p.create_file(&d.join(format!("f{i:05}")).unwrap()).unwrap();
    }
    for i in 0..3 {
        p.create_dir(&d.join(format!("d{i}")).unwrap()).unwrap();
    }
    let (mut sizes, mut seen) = (Vec::new(), BTreeSet::new());
    p.list(&d, &CancelToken::new(), &mut |batch| {
        sizes.push(batch.len());
        for e in batch {
            let want = if e.name.to_string_lossy().starts_with('d') { EntryKind::Dir } else { EntryKind::File };
            assert_eq!(e.kind, want, "{:?}", e.name);
            assert!(seen.insert(e.name), "duplicate entry");
        }
    })
    .unwrap();
    assert!(sizes.len() >= 3 && sizes.iter().all(|&n| n > 0 && n <= LIST_BATCH_SIZE), "{sizes:?}");
    assert_eq!(seen.len(), files + 3);
    let empty = fresh(p, root, "empty");
    let mut calls = 0;
    p.list(&empty, &CancelToken::new(), &mut |_| calls += 1).unwrap();
    assert_eq!(calls, 0);
    assert_eq!(kind_of(p.list(&d.join("missing").unwrap(), &CancelToken::new(), &mut |_| {})), ErrorKind::NotFound);
    assert!(p.list(&d.join("f00000").unwrap(), &CancelToken::new(), &mut |_| {}).is_err());
    sizes
}
```

```rust
use std::collections::BTreeSet;
use std::ffi::OsString;
use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::{Arc, mpsc};
use std::time::{Duration, Instant};

use rf_core::VPath;
use rf_vfs::{Change, LocalProvider, Provider, WatchEvent, WatchHandle, testkit};

const WAIT: Duration = Duration::from_secs(10);

fn start(p: &LocalProvider, dir: &VPath) -> (WatchHandle, mpsc::Receiver<WatchEvent>) {
    let (tx, rx) = mpsc::channel();
    let h = p.watch(dir, Box::new(move |e| {
        let _ = tx.send(e);
    }))
    .unwrap();
    std::thread::sleep(Duration::from_millis(200));
    (h, rx)
}

fn apply(model: &mut BTreeSet<OsString>, ev: WatchEvent, p: &LocalProvider, dir: &VPath) {
    match ev {
        WatchEvent::Changes(changes) => {
            for c in changes {
                match c {
                    Change::Upsert(e) => {
                        model.insert(e.name);
                    }
                    Change::Removed(n) => {
                        model.remove(&n);
                    }
                    Change::Renamed { from, to } => {
                        model.remove(&from);
                        model.insert(to.name);
                    }
                }
            }
        }
        WatchEvent::Rescan => *model = testkit::names(p, dir),
        WatchEvent::Ended => panic!("watch ended unexpectedly"),
    }
}

fn wait_for(rx: &mpsc::Receiver<WatchEvent>, model: &mut BTreeSet<OsString>, p: &LocalProvider, dir: &VPath, want: &[&str]) {
    let want: BTreeSet<OsString> = want.iter().map(OsString::from).collect();
    let deadline = Instant::now() + WAIT;
    while *model != want {
        let left = deadline
            .checked_duration_since(Instant::now())
            .unwrap_or_else(|| panic!("model {model:?} never became {want:?}"));
        if let Ok(ev) = rx.recv_timeout(left) {
            apply(model, ev, p, dir);
        }
    }
}

        if matches!(rx.recv_timeout(left), Ok(WatchEvent::Ended)) {
            break;
        }
    }
```

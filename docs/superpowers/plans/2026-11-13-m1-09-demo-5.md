# M1-09 데모 5판 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PRD의 M1 Alpha 항목 중 Linux에서 만들고 테스트할 수 있는 빈칸을 메운다. 전송의 남은 화면(XFER-01·06·09·11), 기본 작업의 남은 조각(OPS-01·02, NAV-04, PICK-03·04·05, KEY-03), 레이아웃(LAY-03 패널별 트리, LAY-07 창 위치, LAY-09, LAY-10), 보기(NAV-06 썸네일 보기·타일, NAV-07 열), 휴지통과 가상 위치(NAV-16), 테마 토큰·고대비·밀도·글꼴 크기(THEME-01·03·07), 한국어·영어(I18N-01·02)를 더해 데모 0.5.0으로 낸다.

**Architecture:** M1-05~08의 구조를 그대로 쓴다. 순수 상태는 `crates/rf-ui/src/state/*`, Slint 연결은 `controller*.rs`·`ui_bridge.rs`, 화면은 `ui/*.slint`, OS 기능은 `rf-platform`의 OS별 모듈, 파일을 바꾸는 길은 `rf-jobs`.
- **테마:** 새 `crates/rf-ui/src/theme.rs`가 TOML 토큰 파일을 읽어 검증하고, 값을 Slint 전역 `Theme`의 `in` 속성으로 넣는다. 내장 테마(라이트·다크·고대비)는 `crates/rf-ui/themes/*.toml`을 `include_str!`로 싣는다. 밀도와 글꼴 크기는 토큰 위에 곱하는 배율이다.
- **언어:** 새 `crates/rf-ui/src/i18n.rs`가 Project Fluent 묶음(ko, en)을 싣고, `words.rs`는 그 위의 얇은 층이 된다. `.slint`의 문자열은 Slint 전역 `Tr`의 속성으로 옮기고 Rust가 시작할 때 채운다. 원본은 `crates/rf-ui/i18n/{ko,en}/*.ftl` 하나다.
- **휴지통:** `rf-platform::trash`에 목록·비우기를 더하고, `rf-vfs`의 Shell 스킴 공급자가 휴지통과 "내 PC"를 폴더처럼 보인다. 복원과 비우기는 작업 엔진의 작업이다.

**Tech Stack:** M1-08과 같다. 더하는 것: `fluent-bundle`(+`unic-langid`, 필요하면 `intl-memoizer`), `sys-locale`(OS 언어), `toml`(이미 씀). Windows `SystemParametersInfoW(SPI_GETHIGHCONTRAST)`, 휴지통 열거(`IShellFolder`·`IEnumIDList`·`SHEmptyRecycleBinW`), macOS `NSWorkspace.accessibilityDisplayShouldIncreaseContrast`. 새 크레이트는 `cargo deny`를 통과해야 한다.

**Spec:** docs/PRD.md — XFER-01·06·09·11, OPS-01·02, NAV-04·06·07·16, PICK-03·04·05, KEY-03, LAY-03·07(일부)·09·10, THEME-01·03·07·09, I18N-01·02.

## 이전 계획에서 이어받는 것

- M1-05~08 계획의 Global Constraints를 모두 따른다: UI 스레드는 파일을 stat하지 않는다, 세대 번호, 파일 변경은 작업 엔진으로, 단축키는 `keys.rs`의 OS별 배정표 하나에서, OS 코드 위치와 `unsafe` 규칙(`#![allow(unsafe_code, reason)]`, `// SAFETY:`), 대화형 세션이 필요한 테스트는 `#[ignore = "needs an interactive session"]`, 재진입(모달 루프 중 `AppState` 빌림 금지), winit 내부는 건드리지 않는다, 제품 이름은 `rf_core::identity`에서만(Rust 파일에 "racoon" 금지), 자원 제한(`CARGO_BUILD_JOBS=4`, `--test-threads=4` 이하, cargo는 한 번에 하나, `CARGO_INCREMENTAL=0`).
- 테스트는 Windows·macOS 러너에서도 돈다: 시각에 1 ns를 더하지 않는다(Windows 100 ns 단위), 임시 폴더 경로는 `canonicalize`해서 비교한다, macOS의 환경설정은 파일이 아니라 defaults 도메인이다, 실제 HOME·레지스트리를 건드리지 않는다.
- M1-08에서 남긴 사소한 항목(되돌리기 기록 다시 그리기 비용, 썸네일 캐시 버전, 미완성 링크 작업 재실행의 중복, 감시 타이머 100 ms)은 이 계획의 범위가 아니다. 손대는 파일에서 마주치면 고친다.

## Global Constraints (이 계획의 추가분)

- **설정 파일.** 필드를 더하는 것은 기본값으로 읽고 버전을 올리지 않는다. 뜻이 바뀌는 필드가 생길 때만 `SETTINGS_VERSION`을 올리고 `migrate`를 쓴다. 이 계획에서 뜻이 바뀌는 것은 `hide_tree`(bool) → 트리 모드 하나이고(Task 4), 그때 버전 2로 올린다. 0.4.0이 쓴 설정 파일을 읽는 테스트를 둔다.
- **문구.** Task 9 전까지 새 문구는 지금처럼 `words.rs`(한국어)와 `.slint`에 쓴다. Task 9·10이 한꺼번에 Fluent로 옮긴다. Task 9 뒤로는 한글 문자열 리터럴을 Rust(테스트 밖)와 `.slint`에 새로 쓰지 않는다.
- **테스트의 언어는 한국어로 고정한다.** 기존 단언(한국어 문구)을 그대로 둔다. 전역 언어는 시작할 때 한 번만 정하고(재시작 없이 바꾸기는 P1), 테스트에서 전역을 바꾸지 않는다. 영어는 `Localizer` 인스턴스로 시험한다.
- **번역이 빠진 문자열은 영어로 보인다**(I18N-02). ko와 en의 키가 서로 같다는 테스트를 둔다. 키 이름은 `영역-뜻`(예: `menu-new-folder`, `status-items`)이고, 숫자·이름은 Fluent 인자다. 영어의 단·복수는 Fluent 선택자로 쓴다.
- **테마 토큰이 화면 크기의 원본이다.** Task 7 뒤로 `.slint`에 글자 크기 리터럴(`font-size: 12px`)을 쓰지 않는다(`theme.slint` 제외). 이를 지키는 검사 테스트를 둔다. 잘못된 토큰 파일은 거부하고 내장 테마로 남는다(패닉하지 않는다).
- **밀도와 글꼴 크기는 서로 독립이다**(THEME-07). 밀도는 줄 높이와 간격만, 글꼴 크기는 글자만 바꾼다. 창의 최소 크기(900×560)에서 가장 큰 조합도 메뉴와 대화상자가 잘리지 않아야 한다(스크롤로 닿으면 된다).
- **고대비.** 테마가 "시스템"이면 OS의 고대비 설정을 따른다. 색만으로 뜻을 전하는 곳(선택, 놓을 곳, 오류)은 고대비에서 테두리나 글자로도 구분된다.
- **휴지통.** 휴지통 보기에서 "복원"은 작업이고 되돌릴 수 있다(다시 휴지통으로). "비우기"와 휴지통 안의 "영구 삭제"는 확인 창을 거치며 되돌릴 수 없다는 것을 그 창에 적는다. 앱은 휴지통 폴더의 파일을 직접 지우지 않고 OS의 방법(Windows 셸, macOS `NSFileManager`, Linux freedesktop 규격)을 쓴다. 원래 위치를 모르는 항목은 복원 대신 "위치를 골라 꺼내기"(PICK)를 준다.
- **오류 때 묻기**(XFER-09). 기본은 지금처럼 "계속하고 끝에 모아 보기"다. "파일마다 묻기"는 설정이고, 묻는 창은 다시 시도·건너뛰기·중단과 "남은 오류에도 같은 선택"을 준다. 다시 시도는 같은 작업 명세의 실패 항목만 새 작업으로 넣는다(성공한 것을 다시 하지 않는다).
- **창 여러 개는 이 판에 없다**(LAY-07의 나머지, DND-01 창↔창). 창 하나의 위치·크기·최대화만 저장한다. 저장한 위치가 지금의 화면 밖이면 기본 위치로 연다.
- **OS 상호작용 테스트:** 실제 휴지통 열거, OS 고대비, OS 언어는 CI에서 확인할 수 없다. 순수 부분(토큰 검증, 배율, 키 맞춤, 언어 고르기, freedesktop 휴지통 읽기, 정책·재시도 규칙)은 모든 OS에서 테스트하고, 나머지는 손으로 확인할 목록(keyboard.md)에 넣는다.

## Review Focus

- "다시 시도"는 실패한 항목만 다시 한다. 성공한 파일을 덮어쓰거나 두 번 옮기지 않고, 되돌리기 기록은 원래 작업과 다시 시도한 작업을 따로 남긴다. (Task 1: 상태·rf-jobs 테스트 `retrying_the_failures_redoes_only_what_failed`.)
- "더 새 파일만"과 "크기가 다를 때만"은 조건에 맞지 않는 파일을 건드리지 않는다. 묻는 창에서 "남은 충돌에도"를 켜면 그 정책이 남은 것에만 적용된다. (Task 1.)
- 느린 두 번 클릭은 이미 선택된 항목 하나를 다시 눌렀을 때만 이름 바꾸기이고, 더블클릭 시간 안의 두 번째 클릭은 열기다. 끌기를 시작하면 이름 바꾸기가 아니다. (Task 3: 포인터 상태 테스트.)
- 0.4.0의 설정 파일(`hide_tree = true/false`)이 버전 2로 옮겨져 같은 화면으로 열린다. 읽을 수 없는 파일의 백업 규칙은 그대로다. (Task 4.)
- 휴지통 "비우기"와 "영구 삭제"는 확인 없이는 일어나지 않고, 복원은 원래 자리에 같은 이름이 있으면 충돌 규칙을 따른다(덮어쓰지 않는다). (Task 6: rf-platform의 freedesktop 테스트와 상태 테스트.)
- 잘못된 테마 토큰(없는 키, 색이 아닌 값, 음수 크기)은 거부되고 앱은 내장 테마로 뜬다. (Task 7: `theme` 테스트.)
- ko와 en의 Fluent 키가 정확히 같고, `Tr` 전역의 모든 속성이 채워진다. 한국어 화면의 문구는 0.4.0과 글자 하나 다르지 않다(기존 테스트가 그대로 통과). (Task 9·10.)

# M1-07 데모 3판 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 0.2.0 데모의 끌어 놓기를 앱 밖으로 넓힌다. 탐색기·Finder 등 다른 앱과 파일을 끌어 주고받는다(DND-05). 놓을 때의 동작은 OS별 보조키와 설정이 정한다(DND-02·03). 머무르면 열기·자동 스크롤·이동 되돌리기 알림을 더한다(DND-07·08). Windows 셸 우클릭 메뉴와 macOS 공유를 띄운다(OPS-05). 사용자가 자기 PC에서 써 보는 데모 0.3.0으로 낸다.

**Architecture:** M1-05·06의 구조를 그대로 쓴다. 순수 상태는 `crates/rf-ui/src/state/*`, Slint 연결은 `controller.rs`, 문구는 `words.rs`, 화면은 `ui/*.slint`. OS 끌어 놓기와 셸 메뉴는 `rf-platform`의 새 `dnd` 모듈과 `shell` 모듈에 OS별로 둔다.
- **놓기 받기:**
  - Windows는 winit이 등록한 드롭 대상을 앱의 `IDropTarget`으로 바꾼다.
  - macOS는 창 내용 위에 끌기만 받는 투명 뷰를 얹는다.
  - Linux(개발용)는 winit의 `DroppedFile`을 쓴다.
- **끌어내기:** 앱 안 끌기가 창 밖으로 나가는 순간 OS 끌기로 넘긴다(Windows `SHDoDragDrop`, macOS `NSDraggingSession`).
- **위치 찾기:** OS 끌기가 창 위 어디에 있는지는 Slint의 순수 함수 `spot-at`이 앱 안 끌기와 같은 `DropSpot`으로 바꾼다. 그래서 놓을 곳 판단·강조·문구는 앱 안 끌기의 코드를 그대로 쓴다.

**Tech Stack:** M1-06과 같다. 다음을 더한다.
- windows-rs 기능: `Win32_System_Ole`, `Win32_System_SystemServices`, `Win32_UI_WindowsAndMessaging`, `Win32_Graphics_Gdi`, `Win32_UI_HiDpi`, `Win32_UI_Controls`, 필요한 만큼.
- objc2-app-kit 기능: `NSView`, `NSDragging`, `NSDraggingItem`, `NSDraggingSession`, `NSEvent`, `NSImage`, `NSWindow`, `NSSharingServicePicker`, `NSResponder`, 필요한 만큼.
- Slint의 공개 winit 연결: `slint::winit_030::WinitWindowAccessor`의 `on_winit_window_event`와 `with_winit_window`, raw-window-handle.

새 크레이트는 없다. 기능을 더한 뒤 `cargo deny`가 통과해야 한다.

**Spec:** docs/PRD.md — DND-02·03·04(일부)·05·07·08·09, OPS-05. DND-01·06·10·11은 이미 있다.

- M1-05에서 확인된 Slint 1.18.1의 앱 안 끌기 사실(plans/README.md "계획 작성 중 확인된 사실" 4)이 출발점이다.

## Global Constraints (이 계획의 추가분)

- **다른 앱이 끌어 온 이동:** 앱 자신의 작업 엔진으로 이동한다. 복사가 끝난 뒤에만 원본을 지운다.
  - Windows `IDropTarget::Drop`은 `DROPEFFECT_MOVE`를 결코 돌려주지 않는다. 이동이면 `*pdwEffect = DROPEFFECT_NONE`을 돌려주고, 데이터 객체에 `CFSTR_PERFORMEDDROPEFFECT`를 `DROPEFFECT_NONE`으로, `CFSTR_LOGICALPERFORMEDDROPEFFECT`를 `DROPEFFECT_MOVE`로 적는다. 셸이 최적화된 이동 뒤에 적는 값과 같다(실패는 무시). `CFSTR_PERFORMEDDROPEFFECT`에 `DROPEFFECT_MOVE`를 적으면 "받는 쪽이 복사만 했으니 원본을 지워라"(최적화되지 않은 이동)로 읽히므로 결코 적지 않는다.
  - 끌어 온 앱이 "옮겨졌으니 원본을 지워라"로 읽을 결과를 주지 않는다. 그런 앱이 복사가 끝나기 전에 원본을 지우면 데이터를 잃는다.
- **앱 밖으로 끌어낸 이동:** 받는 앱이 OS 규칙대로 한다(DND-05). 앱은 끌어내기가 끝난 뒤 원본을 지우지 않는다. 받는 앱이 복사만 하고 원본 삭제를 끌어 온 쪽에 맡겨도(최적화되지 않은 이동), 결과는 복사로 끝난다.
- **재진입:** OS 끌기(`SHDoDragDrop`)와 셸 메뉴(`TrackPopupMenuEx`)는 UI 스레드에서 도는 모달 루프다. 루프 안에서 앱 자신의 드롭 대상과 Slint 콜백이 다시 불린다. 그래서:
  - 이 호출을 부르는 동안 `AppState`의 `RefCell`을 빌린 채로 두지 않는다. 필요한 값을 꺼내 빌림을 놓은 뒤 부른다.
  - 다음 이벤트 루프 차례로 미뤄 부른다(`slint::Timer::single_shot` 0 ms).
  - 드롭 대상의 콜백은 빌림을 짧게 잡는다. 이미 빌려져 있으면(`try_borrow_mut` 실패) 거절로 답하고 끝낸다.
- **좌표:** rf-platform과 rf-ui 사이에서 주고받는 창 위 위치는 창 내용 기준의 논리 픽셀(`WindowPoint { x: f32, y: f32 }`)뿐이다. 화면 좌표·물리 픽셀·macOS의 뒤집힌 y축은 rf-platform 안에서 바꾼다. 바꾸는 계산은 순수 함수로 두고 모든 OS에서 테스트한다(배율 1.0·1.25·1.5, 왼쪽 모니터의 음수 화면 좌표).
- **창 핸들이 바뀔 수 있다:** 트레이로 숨겼다 다시 보이면 창이 새로 만들어질 수 있다. 드롭 대상 등록은 창 핸들마다 한 번 하고, 창을 보일 때마다 핸들을 다시 확인해 새 핸들이면 다시 등록한다.
- **winit 속은 건드리지 않는다:** winit의 클래스나 창 프로시저를 바꾸지 않는다(swizzling, 서브클래싱 금지). 공개 API(`on_winit_window_event`, `with_winit_window`, raw-window-handle)와 OS의 공개 등록 함수(`RevokeDragDrop`·`RegisterDragDrop`, 하위 뷰 추가)만 쓴다. Slint는 `=1.18.1`로 고정돼 있다.
- **OS 상호작용 테스트:** 실제 끌기와 실제 메뉴는 CI에서 할 수 없으므로 손으로 확인할 목록에 넣는다. 다음 순수 부분은 모든 OS에서 테스트한다: 동작 규칙, 좌표 변환, 앱 자신의 끌기 표시 인코딩, 셸 동사 매핑, `DROPEFFECT` 응답.

## Review Focus

- 탐색기에서 Shift를 누른 채 이 앱으로 끌어 이동하면, 복사가 끝나기 전에는 탐색기 쪽 원본이 사라지지 않는다. 앱이 `DROPEFFECT_MOVE`를 돌려주면 탐색기가 원본을 바로 지운다. (Task 4: 순수 함수 `drop_reply`의 테스트가 돌려줄 값·`CFSTR_PERFORMEDDROPEFFECT`·`CFSTR_LOGICALPERFORMEDDROPEFFECT`를 고정한다. 이동 → `DROPEFFECT_NONE`, `Some(DROPEFFECT_NONE)`, `Some(DROPEFFECT_MOVE)`. 복사 → `DROPEFFECT_COPY`, `Some(DROPEFFECT_COPY)`, `Some(DROPEFFECT_COPY)`. 묻기·거절 → `DROPEFFECT_NONE`, `None`, `None`.)
- 앱에서 끌어내 다른 앱에 놓은 뒤 앱은 아무것도 지우지 않는다. 받는 앱이 무엇을 했든(`DropEffect::Move` 포함) 원본은 받는 앱이 다루지 않았다면 그대로 있다. (Task 5: 상태 테스트 `a_drag_out_that_ends_as_a_move_deletes_nothing`가 끝난 결과마다 돌아온 Effect에 작업 제출이 없음을 확인한다.)
- 배율 125%·150%인 화면, 주 모니터 왼쪽에 있는 모니터에서도 놓이는 곳이 커서 아래의 행이다. (Task 4: `client_point` 테스트에 배율 1.25·1.5와 음수 화면 좌표.)
- 대화상자(확인, 충돌, PICK, 이름 입력, 속성)나 앱 메뉴가 떠 있는 동안 다른 앱에서 끌어 온 것은 받지 않는다(금지 커서, 놓아도 아무 일 없음). 항목이 이미 있는 폴더에 놓아도 아무 일이 없다(DND-09). (Task 3: 상태 테스트 `a_drop_while_a_dialog_shows_is_refused`, `a_drop_into_the_folder_the_items_are_in_does_nothing`.)
- 창을 트레이로 숨겼다가 다시 보이면 창이 새로 만들어질 수 있다. 그 뒤에도 끌어 놓기 받기와 셸 메뉴가 된다. (Task 4: 등록기를 흉내 낸 테스트 `a_new_window_handle_registers_the_drop_target_again`가 같은 핸들에는 한 번, 새 핸들에는 다시 등록하는지 본다.)

## 이 계획이 일부러 다루지 않는 항목

다음 판으로 넘기는 것:
- 링크·바로 가기·별칭 만들기. 끌기의 Alt(Windows)·⌥⌘(macOS)·Ctrl+Shift(Linux)는 "링크 만들기는 아직 없습니다"를 보이고 받지 않는다.
- 압축해서 넣기(DND-04의 그 항목).
- 즐겨찾기 목록에 놓아 추가하기. 사용자가 편집하는 즐겨찾기가 아직 없다.
- 읽기 전용 원본을 복사로 바꾸기(DND-06의 자동 전환). 압축 파일과 원격이 아직 없고, 읽기 전용 볼륨에서의 이동은 작업 엔진이 원본 삭제에서 실패를 보고하고 원본을 남긴다.
- 파일이 아닌 끌기(메일 첨부, 브라우저 이미지, `CFSTR_FILEDESCRIPTOR`). 받지 않는다.
- macOS 서비스와 빠른 동작.
- Linux의 끌어내기와 Wayland의 끌어 놓기.
- 그리고 M1-06이 넘긴 나머지: 썸네일, 탐색기 대체, 설치 프로그램, 다국어, 여러 창.

### Task 1: 놓을 때의 동작 규칙, 보조키, 설정, 놓을 때 묻기 (DND-02·03·04 일부)

**Files:** 새 `crates/rf-platform/src/dnd/mod.rs`(OS 독립 타입만, 이 과제에서는), `crates/rf-platform/src/shell/mod.rs`(`WindowPoint`), 새 `crates/rf-ui/src/state/drop_rule.rs`, `state/drag.rs`, `settings.rs`, `controller.rs`, `ui/app.slint`·`file-list.slint`·`file-grid.slint`, `ui/view-menu.slint`, `words.rs`, `docs/ux/keyboard.md`

**Interfaces:**
- Produces (rf-platform `dnd`):
  - `pub enum DropEffect { Copy, Move, Link }`
  - `pub struct Effects(u8)`: 상수 `COPY`·`MOVE`·`LINK`·`ALL`, `contains(DropEffect) -> bool`, `BitOr`.
  - `pub struct DragMods { pub ctrl: bool, pub shift: bool, pub alt: bool, pub logo: bool }`. `logo`는 macOS의 ⌘, Windows의 Win 키다.
  - `pub struct DroppedItems { pub paths: Vec<PathBuf>, pub ours: Option<u64> }`. `ours`는 이 앱이 끌어낸 끌기의 id다(Task 5).
- Produces (rf-platform `shell`): `pub struct WindowPoint { pub x: f32, pub y: f32 }`. 창 내용 기준의 논리 픽셀이다.
- Produces (rf-ui):
  - `settings::DragDefault { Move, Copy, System, Ask }`(기본 `Move`)
  - `Settings::drag_default`, `Settings::move_undo_toast: bool`(기본 true, Task 2가 쓴다), `Settings::system_menu_first: bool`(기본 false, Task 6이 쓴다). 셋 다 하위 호환 기본값으로 읽는다.
  - `drop_rule::choose(os: Os, default: DragDefault, mods: DragMods, allowed: Effects, same_volume: bool) -> DropChoice`
  - `pub enum DropChoice { Do(DropEffect), Ask, Refuse(Refusal) }`, `pub enum Refusal { NoLinks, NotAllowed }`
  - `drop_rule::same_volume(a: &Path, b: &Path, roots: &[PathBuf]) -> bool`
  - `AppState::modifiers_changed(DragMods)`

- [ ] **규칙 테스트.** `state/tests/drop_rule.rs`. 세 OS 모두 Linux에서 돈다. 다음을 단언한다.
  - Windows: Ctrl → Copy, Shift → Move, Alt → `Refuse(NoLinks)`, Ctrl+Shift → `Refuse(NoLinks)`.
  - macOS: ⌥ → Copy, ⌘ → Move, ⌥⌘ → `Refuse(NoLinks)`. Ctrl은 macOS에서 동작을 바꾸지 않는다.
  - Linux: Ctrl → Copy, Shift → Move, Ctrl+Shift → `Refuse(NoLinks)`.
  - 보조키가 없으면 설정을 따른다. `Move` → Move, `Copy` → Copy, `System` → 같은 볼륨이면 Move이고 아니면 Copy, `Ask` → Ask.
  - 보조키가 고른 동작이 `allowed`에 없으면 `Refuse(NotAllowed)`.
  - 설정의 동작이 `allowed`에 없으면 Move → Copy 순서로 내려간다(DND-05: 이동을 허용하지 않으면 복사). 둘 다 없으면 `Refuse(NotAllowed)`. `Ask`는 Copy나 Move가 허용될 때만 Ask다.
- [ ] **같은 볼륨 테스트.** `same_volume`은 사이드바가 이미 작업 스레드에서 받은 드라이브 목록(`places.rs`의 드라이브 루트들)에서 각 경로가 속한 가장 긴 루트를 비교하는 순수 함수다.
  - 테스트 예: `C:\a`와 `C:\b`는 같다. `C:\a`와 `D:\b`는 다르다. 루트가 `/`와 `/Volumes/USB`이면 `/Users/x`와 `/Volumes/USB/y`는 다르다.
  - 어느 루트에도 들지 않으면 다르다고 본다(복사 쪽이 안전하다).
- [ ] **규칙 구현.** `drop_rule.rs`를 구현한다. 앱 안 끌기의 `drop-check`·`dropped`가 Slint가 고른 `DragAction`이 아니라 `choose`의 결과를 돌려주게 바꾼다.
  - 보조키는 controller가 `on_winit_window_event`의 `ModifiersChanged`로 받아 `AppState::modifiers_changed`로 넘긴다. Slint의 `DropEvent`에는 보조키가 없다.
  - Slint의 끌기 커서가 보조키를 따르게 해 본다. 지금 보조키에 맞게 `DragArea`의 `allow-move`·`allow-copy`를 바꾸는 식이다. 끄는 도중에 커서가 바뀌지 않으면 그 사실을 keyboard.md의 알려진 차이에 적는다. 앱이 하는 동작은 언제나 아래 문구가 맞힌다.
- [ ] **커서 옆 문구(DND-03).** M1-05의 "목록 아래 문구"를 커서 옆 작은 배지로 바꾼다.
  - 배지는 `DropArea`가 받는 포인터 위치를 창 좌표로 옮겨, 창 위 겹침 요소로 그린다.
  - 문구는 words.rs에 둔다: "이동 → {폴더}", "복사 → {폴더}", "놓을 때 묻기 → {폴더}", "링크 만들기는 아직 없습니다", "여기에는 놓을 수 없습니다".
  - 900×560 스크린샷에서 확인한다.
- [ ] **놓을 때 묻기(DND-02 "매번 묻기", DND-04).** `Ask`로 놓으면 놓은 자리에 앱 메뉴를 띄운다: "여기로 이동", "여기로 복사", "취소".
  - 고르면 같은 `drop_items` 길로 작업을 낸다. Esc와 바깥 클릭은 취소다.
  - 앱 안 오른쪽 버튼 끌기는 Slint가 시작하지 않는다. keyboard.md에 적고, "매번 묻기" 설정을 대신 안내한다.
  - 상태 테스트: Ask로 놓으면 작업이 없고 메뉴 Effect가 나온다. 메뉴의 이동이 `TransferMode::Move` 작업을 낸다.
- [ ] **설정 UI.** 보기 메뉴(F10, macOS ⌘J) 맨 아래에 "설정" 하위 메뉴를 만든다.
  - "끌어 놓기 기본 동작"(이동·복사·OS 방식·매번 묻기, 고른 것에 표시).
  - "끌어서 옮긴 뒤 되돌리기 알림"(켜고 끄기).

### Task 6: Windows 셸 메뉴와 macOS 공유 (OPS-05)

**Files:** `crates/rf-platform/src/shell/{mod,windows,macos,other}.rs`, `crates/rf-ui/src/state/shell.rs`, `controller.rs`, `ui/list-parts.slint`(항목·빈 곳 메뉴), `keys.rs`, `words.rs`, `docs/ux/keyboard.md`

**Interfaces:**
- Consumes: `Owner`(Task 4), `WindowPoint`·`Settings::system_menu_first`(Task 1).
- Produces:
  - `pub fn system_menu(owner: Owner, folder: &Path, names: &[OsString], at: WindowPoint, extended: bool) -> io::Result<SystemMenuChoice>`. Windows만이고, 다른 OS는 `Unsupported`다. `names`가 비면 폴더 자신(빈 곳)의 메뉴다.
  - `pub enum SystemMenuChoice { Nothing, Done, App(AppVerb) }`
  - `pub enum AppVerb { Rename, Delete { permanent: bool }, Cut, Copy, Paste }`
  - 순수 `pub fn app_verb(verb: &str, shift: bool) -> Option<AppVerb>`
  - `pub fn share(owner: Owner, paths: &[PathBuf], at: WindowPoint) -> io::Result<()>`. macOS만이다.
  - `Command::SystemMenu`(배정표).
- [ ] **`app_verb` 테스트.** 모든 OS에서 돈다.
  - "rename" → Rename, "delete" → `Delete{permanent: shift}`, "cut"·"copy"·"paste" → 같은 이름.
  - 대소문자를 무시한다. "properties", "open", "link" 등 나머지는 None.
- [ ] **Windows 메뉴.**
  - 폴더 PIDL(`SHParseDisplayName`)에서 `IShellFolder`(`SHBindToObject`)를 얻고, 이름마다 `ParseDisplayName`으로 자식 PIDL을 만든다.
  - `GetUIObjectOf(IID_IContextMenu)`로 메뉴 객체를 얻는다. 빈 곳이면 `CreateViewObject(IID_IContextMenu)`다.
  - `QueryContextMenu(CMF_NORMAL | CMF_CANRENAME | (extended ? CMF_EXTENDEDVERBS : 0))`로 메뉴를 채운다.
  - `TrackPopupMenuEx(TPM_RETURNCMD | TPM_RIGHTBUTTON)`로 띄운다.
    - 메뉴의 주인은 rf-platform이 만든 숨은 도우미 창이다. 그 창 프로시저가 `WM_INITMENUPOPUP`·`WM_DRAWITEM`·`WM_MEASUREITEM`·`WM_MENUCHAR`를 `IContextMenu3::HandleMenuMsg2`(없으면 `IContextMenu2::HandleMenuMsg`)로 넘긴다. "보내기"·"연결 프로그램" 하위 메뉴가 채워지게 하려는 것이다.
    - winit의 창 프로시저는 서브클래싱하지 않는다.
    - 띄우기 전에 `SetForegroundWindow(owner)`를 부른다.
  - 고른 명령의 동사(`GetCommandString(GCS_VERBW)`)가 `app_verb`에 들면 `App(..)`을 돌려준다. 앱이 자기 명령으로 한다: 이름 바꾸기, 휴지통·영구 삭제(작업 엔진과 되돌리기), 클립보드.
  - 나머지는 `InvokeCommand(CMINVOKECOMMANDINFOEX)`를 부른다: 유니코드, `ptInvoke`, 지금의 Shift·Ctrl 상태, `hwnd`=owner, `SW_SHOWNORMAL`. 그리고 `Done`이다.
  - UI 스레드에서 다음 이벤트 루프 차례에, 빌림 없이 부른다.
- [ ] **rf-ui.** Windows에서 항목 메뉴와 빈 곳 메뉴 맨 아래에 "더 많은 옵션 표시"를 둔다(Windows 11 탐색기의 문구와 키).
  - Shift+F10과 Shift+오른쪽 클릭은 Windows 메뉴를 바로 띄운다. Windows 11 탐색기와 같다.
  - 메뉴 키와 오른쪽 클릭은 앱 메뉴를 띄운다. 설정 "오른쪽 클릭에 Windows 메뉴 바로 띄우기"를 켜면 둘 다 Windows 메뉴다.
  - 배정표(`keys.rs`), keyboard.md의 항목 메뉴 줄, KEY-02 표를 고친다. macOS·Linux의 키는 그대로다.
  - 메뉴는 오른쪽 클릭한 자리에, 키로 열면 M1-06의 항목 메뉴 자리 규칙대로 뜬다.
  - `App(..)`은 기존 명령으로 보낸다. 상태 테스트: `App(Delete{permanent:false})` → 휴지통 작업, `App(Rename)` → 이름 바꾸기 시작, `Done`·`Nothing` → 아무 Effect 없음.

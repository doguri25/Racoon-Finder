> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 0.3.0 데모를 "탐색기처럼 보이고, 설치해서 쓰는" 쪽으로 넓힌다. 아이콘 보기에 OS 썸네일을 보이고(VIEW-09), 즐겨찾기를 사용자가 고치고 끌어 놓아 더하며(NAV-05, DND-01), 링크를 만들고(OPS-08, DND-03의 링크 키), 마우스 4·5번 버튼·트랙패드·길게 누르기·체크박스 선택을 받고(NAV-04, PICK-02, NAV-15), 되돌리기 기록을 보이고(OPS-12), Windows 설치 프로그램과 macOS 디스크 이미지, 클린 삭제, 설정 버전을 더한다(INST-01·03·04·05·08). 사용자가 자기 PC에 설치해 써 보는 데모 0.4.0으로 낸다.

**Architecture:** M1-05~07의 구조를 그대로 쓴다. 순수 상태는 `crates/rf-ui/src/state/*`, Slint 연결은 `controller.rs`, 문구는 `words.rs`, 화면은 `ui/*.slint`. OS 기능은 `rf-platform`의 OS별 모듈에 둔다.
- **썸네일:** `rf-platform::thumbs`가 OS 공급자(Windows `IShellItemImageFactory`, macOS `QLThumbnailGenerator`)를 부르고, 없거나 실패하면 rf-ui의 자체 디코더(`preview::decode_image`)로 보완한다. 작업 스레드 풀에서 보이는 항목부터 만들고, 메모리 LRU와 디스크 캐시(`AppPaths::cache_dir()/thumbs`)에 둔다. 외부 코드는 `guarded`(catch_unwind)와 감시 타이머로 감싼다. 보조 프로세스 격리(VIEW-08, P1)는 다음 판이다.
- **링크:** 새 `JobSpec::MakeLink`가 작업 엔진에서 만들고 되돌리기 기록을 남긴다. OS별 생성은 `rf-platform::links`.
- **설치:** Windows는 Inno Setup 스크립트(`installer/windows/racoon-finder.iss`)를 CI가 빌드한다. 사용자 단위 설치, 시작 메뉴 바로 가기에 AUMID. 제거는 앱 자신의 `--cleanup`이 rf-ledger의 `run_cleanup`으로 한다. macOS는 `hdiutil` 디스크 이미지와 앱 안의 "완전 삭제…"다.
- **원칙:** OS를 바꾸는 코드는 rf-ledger를 거친다(INST-02). 파일을 바꾸는 길은 작업 엔진을 거친다. 설치 프로그램 자신이 만드는 것(설치 폴더, 바로 가기, 제거 등록)은 제거 프로그램이 지운다.

Inno Setup 6(windows-latest 러너에 설치돼 있음, `ISCC.exe`). 새 크레이트는 `cargo deny`를 통과해야 한다.

## 이전 계획에서 이어받는 것

- M1-05·06·07 계획의 Global Constraints를 모두 따른다: UI 스레드 규칙과 세대 번호, 파일 변경은 작업 엔진으로, 문구는 words.rs와 .slint, 단축키는 `keys.rs` 배정표 하나에서, OS 코드 위치와 `unsafe` 규칙, 대화형 세션이 필요한 테스트는 `#[ignore]`, 재진입(모달 루프 중 `AppState` 빌림 금지), 자원 제한(`CARGO_BUILD_JOBS=4`, `--test-threads=4` 이하, cargo는 한 번에 하나, 스크린샷과 실제 실행은 새 HOME에서).
- UI 코드가 직접 쓰는 파일의 예외 목록(설정, 인스턴스 잠금, 작업 로그, 창 보이기 요청, startup-error.log)에 이 계획은 **썸네일 디스크 캐시**(`cache_dir()/thumbs`, 앱 자신의 캐시 파일만, 작업 스레드에서)와 **설정 백업**(`settings.toml.bak-<시각>`, INST-08)을 더한다.
- M1-07에서 미룬 사소한 항목(`.superpowers` 원장의 "minor (deferred)")은 이 계획의 범위가 아니다. 손대는 파일에서 마주치면 고친다.

## Global Constraints (이 계획의 추가분)

- **썸네일은 목록을 막지 않는다.** 목록은 종류별 아이콘으로 먼저 그려지고, 썸네일은 도착하는 대로 바뀐다. 한 파일의 공급자가 느리거나(감시 타이머 5초) 패닉하거나 실패하면 그 파일만 종류별 아이콘으로 남고, 다른 파일의 썸네일은 계속 온다. UI 스레드는 디코딩하지 않는다.
- **썸네일 요청은 세대 번호와 보이는 범위를 따른다.** 보이는 항목부터, 스크롤하면 보이지 않게 된 요청은 버린다. 폴더를 바꾸면 이전 폴더의 요청은 모두 버린다.
- **캐시 키는 경로·크기·수정 시각·요청 크기**다. 디스크 캐시는 `cache_dir()/thumbs/<크기>/<해시>.png`이고, 총량 상한(기본 256 MiB)을 넘으면 오래된 것부터 지운다. 캐시는 앱 자신의 파일이므로 UI 코드가 작업 스레드에서 쓰고 지운다.
- **링크 만들기는 작업이다.** `JobSpec::MakeLink`가 만들고, 되돌리기는 그 링크가 아직 같은 대상을 가리키는 링크일 때만 지운다. 대상은 결코 건드리지 않는다. 관리자 권한이 필요한 종류(Windows 심볼릭 링크, 개발자 모드가 꺼진 PC)는 시작 전에 알리고 만들지 않는다.
- **즐겨찾기에 놓기는 이동이 아니다.** 즐겨찾기 목록의 빈 곳이나 항목 사이에 폴더를 놓으면 즐겨찾기 추가이고, 파일은 받지 않는다. 즐겨찾기 항목 위에 놓으면 그 폴더로의 이동·복사다(기존 규칙).
- **OS를 바꾸는 코드는 rf-ledger를 거친다**(INST-02). 이 계획에서 앱이 OS에 쓰는 것은 없어야 한다. 설치 프로그램이 만드는 것(설치 폴더, 시작 메뉴·바탕 화면 바로 가기, 제거 등록 키)은 Inno Setup이 기록하고 제거 프로그램이 지운다. 앱의 `--cleanup`은 rf-ledger의 `run_cleanup`만 부른다.
- **데이터 위치**(INST-03)는 `AppPaths`가 이미 정한 곳뿐이다. 설치형: Windows `%APPDATA%\RacoonFinder`(설정), `%LOCALAPPDATA%\RacoonFinder`(캐시·로그); macOS `~/Library/Application Support|Caches|Logs/<번들 ID>`. 포터블(`portable` 표시 파일)은 `.\data`. 제거 프로그램은 포터블 설치를 건드리지 않는다.
- **설정 파일에 버전을 둔다**(INST-08). 읽을 수 없는 설정은 덮어쓰지 않고 `settings.toml.bak-<시각>`으로 옮긴 뒤 기본값으로 시작하며, 창을 연 뒤 알린다.
- **서명·공증은 이 판에도 없다.** 설치 프로그램과 디스크 이미지도 서명하지 않으므로 처음 열 때 OS가 경고한다. README와 릴리즈 노트에 적는다.
- **OS 상호작용 테스트:** 실제 썸네일 공급자, 실제 .lnk·별칭, 설치·제거는 CI에서 할 수 없다. 순수 부분(캐시 키와 상한 계산, 보이는 범위 스케줄링, 링크 작업의 검증과 되돌리기 규칙, 정리 계획, 설정 이전)은 모든 OS에서 테스트하고, 나머지는 손으로 확인할 목록에 넣는다.

## Review Focus

- 썸네일 공급자가 한 파일에서 멈추거나 패닉해도 창이 멈추지 않고, 그 파일만 종류별 아이콘으로 남으며, 다른 파일의 썸네일은 계속 온다. (Task 2: 가짜 공급자(잠드는 것, 패닉하는 것)로 `thumbs` 풀을 돌리는 테스트.)
- 즐겨찾기 목록의 빈 곳이나 항목 사이에 폴더를 놓으면 즐겨찾기만 늘고 파일은 하나도 움직이지 않는다. 항목 위에 놓으면 그 폴더로 옮긴다. (Task 3: 상태 테스트 `a_folder_dropped_between_favorites_is_added_and_nothing_moves`.)
- 링크 만들기의 되돌리기는 링크만 지운다. 그 자리에 이제 링크가 아닌 것이 있거나 다른 대상을 가리키면 되돌리기를 거절한다. 대상은 어떤 경우에도 지우지 않는다. (Task 4: rf-jobs 테스트 `undoing_a_link_removes_only_the_link_it_made`.)
- 길게 누르기: 시간이 되기 전에 끌기 임계값을 넘으면 메뉴가 아니라 끌기이고, 시간 전에 떼면 클릭이다. 입력란·대화상자 위에서는 동작하지 않는다. (Task 5: 상태·smoke 테스트.)
- 제거 프로그램은 "설정 백업"을 끄면 앱의 데이터 폴더를 모두 지우고 그 밖에는 아무것도 지우지 않으며, 켜면 문서 폴더에 백업 파일 하나만 남긴다. 포터블 설치에는 손대지 않는다. (Task 7: `--cleanup`의 순수 계획 테스트(rf-ledger `plan_cleanup` 위에서 백업 단계), 손으로 확인할 목록.)

### Task 1: 썸네일 공급자 (VIEW-09, rf-platform)

**Files:** 새 `crates/rf-platform/src/thumbs/{mod,windows,macos,other}.rs`, `crates/rf-platform/Cargo.toml`(기능·크레이트), `crates/rf-platform/src/lib.rs`

**Interfaces:**
- Produces:
  - `pub struct Thumb { pub width: u32, pub height: u32, pub rgba: Vec<u8> }` — 미리 곱하지 않은(straight) RGBA, 위에서 아래로.
  - `pub enum ThumbOutcome { Made(Thumb), None, Failed(String) }` — `None`은 "이 형식은 OS가 썸네일을 주지 않음"(종류별 아이콘으로 남김), `Failed`는 다시 시도할 수 있는 실패.
  - `pub fn os_thumbnail(path: &Path, size: u32) -> ThumbOutcome` — 작업 스레드에서 부른다. Linux는 `None`.
  - `pub fn supports_os_thumbnails() -> bool`.
  - 순수: `pub fn fit_within(w: u32, h: u32, size: u32) -> (u32, u32)`(비율 유지 축소), `pub fn bgra_to_rgba_rows(bytes: &[u8], w: u32, h: u32, stride: usize, bottom_up: bool) -> Vec<u8>`.
- [ ] 순수 함수 테스트(모든 OS): `fit_within`의 정사각·가로·세로·작은 그림(키우지 않음), `bgra_to_rgba_rows`의 stride 패딩과 아래위 뒤집힘, 알파 0인 픽셀의 처리(DIB는 알파가 없을 수 있으므로 알파 채널이 모두 0이면 255로 채운다).
- [ ] **Windows:** `SHCreateItemFromParsingName` → `IShellItemImageFactory::GetImage(SIZE{size,size}, SIIGBF_THUMBNAILONLY | SIIGBF_BIGGERSIZEOK)`. `E_FAIL`·`WINCODEC_ERR_*`처럼 "썸네일 없음"은 `None`, 나머지는 `Failed(코드)`. `HBITMAP`은 `GetObjectW`로 `BITMAP`을 읽고 `GetDIBits`(32bpp, top-down)로 꺼낸 뒤 `DeleteObject`. 호출 스레드는 COM STA를 연다(`clipboard/windows.rs`의 방식). 모든 핸들은 RAII로 해제한다.
- [ ] **macOS:** `QLThumbnailGenerator.sharedGenerator`에 `QLThumbnailGenerationRequest(fileAtURL:size:scale:representationTypes: .thumbnail)`을 보내고 완료 핸들러에서 `NSImage`→`CGImage`→RGBA로 바꿔 채널로 돌려준다. 호출 스레드는 채널을 기다린다(감시 타이머는 Task 2의 풀이 한다). 핸들러는 `block2`로 만든다. 주 스레드를 요구하지 않는 API인지 확인하고, 요구하면 `Failed("needs main thread")`를 돌려주고 보고서에 적는다.
- [ ] **Linux:** `None`.
- [ ] `#![allow(unsafe_code, reason)]`와 `// SAFETY:`. clippy를 Windows·macOS 대상으로 돌린다. 손으로 확인할 목록(Windows: JPG·PNG·HEIC·MP4·PDF·DOCX; macOS: 같은 형식과 Keynote; 둘 다: 손상된 JPG, 0바이트 파일, 100 MB JPG의 시간).
- [ ] 커밋: `feat(rf-platform): ask the system for a file's thumbnail`.

### Task 2: 썸네일 보기 (VIEW-09, NAV-06 아이콘 크기)

**Files:** 새 `crates/rf-ui/src/thumbs.rs`(풀·캐시·스케줄), 새 `crates/rf-ui/src/controller/thumber.rs`, `crates/rf-ui/src/state/view.rs`(크기 단계), `ui/file-grid.slint`, `ui/view-menu.slint`, `keys.rs`, `settings.rs`, `words.rs`, `docs/ux/keyboard.md`

**Interfaces:**
- Consumes: Task 1의 `os_thumbnail`, `preview::decode_image`·`image_format`(M1-06), `AppPaths::cache_dir()`.
- Produces:
  - `thumbs::ThumbPool::new(workers: usize, cache_dir: PathBuf, provider: Arc<dyn Fn(&Path, u32) -> ThumbOutcome + Send + Sync>) -> ThumbPool` — 테스트는 가짜 공급자를 넣는다.
  - `ThumbPool::want(&self, folder_generation: u64, items: Vec<ThumbWant>)` — 보이는 범위의 항목들(`ThumbWant { path, size, mtime, len, visible_rank }`). 이전 호출의 아직 하지 않은 요청은 버린다.
  - `ThumbPool::take_ready(&self) -> Vec<ThumbReady>` — UI 스레드가 타이머로 거둔다(`ThumbReady { generation, path, size, image: slint::Image 또는 None }`).
  - 순수: `thumbs::cache_key(path, len, mtime, size) -> String`, `thumbs::prune_plan(entries: &[(PathBuf, u64, SystemTime)], cap: u64) -> Vec<PathBuf>`(오래된 것부터 지울 목록), `thumbs::schedule(wants: &[ThumbWant]) -> Vec<ThumbWant>`(visible_rank 순).
  - `const THUMB_TIMEOUT: Duration = 5 s`, `const CACHE_CAP: u64 = 256 MiB`, 크기 단계: 보통 48, 크게 96, 특대 160(논리 px; 배율만큼 곱해 요청).
- [ ] **풀 테스트(모든 OS, 가짜 공급자):** 보이는 순서대로 만든다; 새 `want`가 이전 요청을 버린다; 세대가 다른 결과는 버린다; 잠드는 공급자(`THUMB_TIMEOUT`보다 길게)는 그 요청만 `Failed`로 끝나고 다음 요청은 새 작업자가 이어서 한다; 패닉하는 공급자는 `guarded`로 잡혀 그 파일만 실패한다; 디스크 캐시 적중은 공급자를 부르지 않는다; `prune_plan`은 상한을 넘는 만큼만 오래된 것부터 고른다.

# M1-10 데모 6판 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** M1-09가 넘긴 것 중 Linux에서 만들고 테스트할 수 있는 것을 메워 데모 0.6.0으로 낸다. 범위는 다음과 같다.
- 휴지통 보내기와 영구 삭제의 다시 시도(XFER-09의 나머지)
- 작업 패널의 높이 상한과 떠 있는 작업 창의 키 위치
- 재시작 없는 언어 전환(I18N-01의 P1)
- 주 창에 딸린 작업 창(LAY-09)
- 앱이 그리는 메뉴
- 창 여러 개(LAY-07의 나머지)
- 창 사이 끌어 놓기(DND-01의 창↔창)

**Architecture:** M1-05~09의 구조를 그대로 쓴다. 순수 상태는 `crates/rf-ui/src/state/*`, Slint 연결은 `controller*.rs`와 `ui_bridge.rs`, 화면은 `ui/*.slint`, OS 기능은 `rf-platform`의 OS별 모듈, 파일을 바꾸는 길은 `rf-jobs`다.
- **창 여러 개:** 작업 엔진·변경 원장·설정 저장기·썸네일 캐시는 한 프로세스에 하나이고 모든 창이 나눠 쓴다. 창마다 `AppState`와 `Controller`가 있다. 앱 쪽에는 새 `crates/rf-ui/src/windows.rs`(`Windows` 목록)가 창을 만들고 닫고 순서를 기억한다.
- **메뉴:** 새 `ui/menu.slint`의 `AppMenu`(PopupWindow)가 `ContextMenuArea`를 모두 대신한다. 메뉴 항목은 Rust의 순수 모델 `crates/rf-ui/src/state/menu.rs`(`MenuModel`)에서 오고, 키 이동·하위 메뉴·스크롤·높이 계산도 순수 함수로 시험한다.
- **언어 전환:** `i18n`의 전역 언어를 바꿀 수 있게 한다. 바뀌면 모든 창을 다시 채우고(`ui_bridge::speak`), Rust가 만든 문자열 모델(행, 상태 줄, 작업 줄, 알림, 메뉴)도 다시 만든다.

**Tech Stack:** M1-09와 같다. OS 쪽에 더하는 것은 다음과 같다.
- 딸린 창: Windows `SetWindowLongPtrW(GWLP_HWNDPARENT)`, macOS `NSWindow addChildWindow:ordered:`, X11 `WM_TRANSIENT_FOR`, Wayland `xdg_toplevel.set_parent`.
- 위 OS 기능은 모두 `raw-window-handle`로 Slint 창의 핸들을 얻어 부른다.
- 새 크레이트는 `cargo deny`를 통과해야 한다.

**Spec:** docs/PRD.md — LAY-07, LAY-09, DND-01, XFER-09, I18N-01(P1 부분), THEME-03, THEME-07(메뉴 쪽). M1-09의 이어받기 목록은 docs/superpowers/plans/README.md "아직 없는 계획".

## 이전 계획에서 이어받는 것

- M1-05~09 계획의 Global Constraints를 모두 따른다.
  - UI 스레드는 파일을 stat하지 않는다.
  - 파일 변경은 작업 엔진으로 한다.
  - 단축키는 `keys.rs`의 OS별 배정표 하나에서 정한다.
  - `unsafe` 규칙: `#![allow(unsafe_code, reason)]`와 `// SAFETY:` 주석을 쓴다.
  - 재진입: 모달 루프 중에는 `AppState`를 빌리지 않는다.
  - 제품 이름은 `rf_core::identity`에서만 쓴다.
  - 자원 제한: `CARGO_BUILD_JOBS=4`, `--test-threads=4` 이하, cargo는 한 번에 하나, `CARGO_INCREMENTAL=0`.
- 테스트는 Windows·macOS 러너에서도 돈다.
  - 시각에 1 ns를 더하지 않는다.
  - 임시 폴더 경로는 `canonicalize`해서 비교한다.
  - 실제 HOME·레지스트리·휴지통을 건드리지 않는다.
  - **글자로 잰 크기를 고정 숫자와 비교하지 않는다.** 러너마다 글꼴이 다르므로 잰 값으로 규칙을 확인한다.
- 문구는 Fluent 파일(`crates/rf-ui/i18n/{ko,en}/*.ftl`)에만 쓴다.
  - Rust(테스트 밖)와 `.slint`에 한글 리터럴을 쓰지 않는다. 검사 테스트가 지킨다.
  - 창은 `ui_bridge`의 만드는 함수로만 만든다. 검사 테스트가 지킨다.
- 테마 토큰이 크기·색의 원본이다. `theme.slint` 밖에 글자 크기와 색 리터럴을 쓰지 않는다.
- 보통·100%의 화면은 이 계획이 일부러 바꾸는 것 말고는 0.5.0과 픽셀 하나 다르지 않다. 바뀌는 것은 메뉴와 딸린 작업 창이다.

## Global Constraints (이 계획의 추가분)

- **설정 파일.**
  - 창 하나의 위치(`window`) 대신 창 목록(`windows = [{…}]`)을 쓴다. 뜻이 바뀌므로 `SETTINGS_VERSION`을 3으로 올리고 `migrate`가 2의 `window`를 목록의 첫 창으로 옮긴다.
  - 0.5.0이 쓴 설정 파일을 읽는 테스트를 둔다.
  - 그 밖의 새 키는 기본값으로 읽고 버전을 올리지 않는다.
- **창 여러 개.**
  - 엔진·원장·설정 저장기·썸네일 캐시는 하나다. 창을 닫아도 그 창이 시작한 작업은 끝까지 간다.
  - 작업 패널은 어느 창에서나 같은 작업을 보인다.
  - 마지막 창을 닫을 때만 지금의 "진행 중인 작업이 있으면 묻기"를 따른다.
  - 창이 다른 창의 `AppState`를 빌리지 않는다. 창 사이의 알림은 메시지(`WindowEvent`)로 보낸다.
- **창↔창 끌어 놓기.** 앱 안의 다른 창에 놓는 것은 패널↔패널과 같은 규칙이다. 기본은 이동이고, 보조키와 "놓을 때" 설정이 같게 적용된다. 다른 앱에서 온 끌기와 구분하는 표지는 OS 끌기 자료에 넣는 앱 고유 형식 하나다.
- **메뉴.**
  - 모든 메뉴가 앱이 그리는 `AppMenu`다. OS의 메뉴 막대(macOS)는 이 계획의 범위가 아니다.
  - 메뉴는 테마·고대비·글자 크기를 따른다.
  - 키보드가 놓인 항목은 고대비에서 막대와 테두리로도 보인다.
  - 창보다 긴 메뉴는 스크롤된다.
  - Esc는 하위 메뉴 하나만 닫는다. 메뉴가 닫히면 키보드는 연 곳으로 돌아간다.
  - 화면 읽기 프로그램에는 `accessible-role: menu`와 `menu-item`, 선택 상태가 보인다.
- **언어 전환.**
  - 바꾸면 바로 모든 창의 모든 문구가 바뀐다. 이미 떠 있는 대화상자도 바뀐다. 사용자가 입력하던 칸은 그대로 둔다.
  - 테스트에서 전역 언어를 바꾸는 것은 자기 테스트 바이너리(`crates/rf-ui/tests/language_switch.rs`) 하나뿐이다. 다른 테스트는 한국어로 고정한다.
- **다시 시도(XFER-09).** 휴지통 보내기와 영구 삭제의 다시 시도도 실패한 항목만 한다. 다른 볼륨(마운트 지점) 실패는 다시 하지 않는다. 다시 하면 그 볼륨 전체를 지우기 때문이다. 영구 삭제의 다시 시도는 확인 창을 다시 거친다.
- **OS 상호작용 테스트.** 딸린 창, 여러 창의 OS 끌기, 실제 메뉴 화면 읽기는 CI에서 확인할 수 없다.
  - 순수 부분은 모든 OS에서 테스트한다. 메뉴 모델, 창 목록, 설정 이전, 다시 시도 규칙, 끌기 표지 판단, 언어 전환의 다시 채우기가 여기에 든다.
  - 나머지는 keyboard.md의 손으로 확인할 목록에 넣는다.

## Review Focus

- **삭제의 다시 시도는 실패한 것만 지운다.** 지운 폴더 안의 마운트 지점(`OtherVolume`)은 다시 시도에 들지 않는다. 영구 삭제의 다시 시도는 확인 창을 거치고, 취소하면 다시 시도가 남는다. (Task 1 테스트 `retrying_a_delete_never_enters_another_volume`)
- **창을 닫아도 작업은 계속된다.** 여러 창 중 하나를 닫아도 그 창이 시작한 작업은 끝나고, 남은 창의 작업 패널에 보이며, 되돌리기도 된다. 마지막 창을 닫을 때만 묻는다. (Task 6 테스트 `closing_a_window_keeps_its_jobs`)
- **대화상자가 떠 있을 때 언어를 바꿔도 된다.** 떠 있는 대화상자와 작업 줄의 문구가 바뀌고, 입력하던 칸의 글자는 그대로이며, 한 화면에 두 언어가 섞이지 않는다. (Task 3 테스트 `switching_the_language_rewords_an_open_dialog`)
- **창보다 긴 메뉴도 끝까지 닿는다.** 900×560, 넉넉하게 + 130%, 영어에서 키보드와 휠로 모든 항목에 닿는다. Esc를 누르면 연 곳으로 돌아간다. (Task 5 테스트 `a_menu_taller_than_the_window_scrolls_to_every_item`)
- **같은 폴더를 연 두 창은 서로를 따라간다.** 한 창에서 이름을 바꾸면 다른 창에도 보인다. 두 창 사이에 끌어 놓으면 이동이고, 되돌리기 한 번에 돌아온다. (Task 7 테스트 `a_drop_from_another_window_of_the_app_moves`)

# Translating the app (I18N-01·02)

The app speaks Korean (`ko`, the original) and English (`en`, which also stands in for anything a
language lacks). Every word it shows, in the window and from Rust, comes from
[Project Fluent](https://projectfluent.org/) files. This page says where they are, how they are
written, how to check a translation, and what a new language needs.

## Where the words are

- `crates/rf-ui/i18n/<language>/<area>.ftl`: one folder per language, one file per area of the app
  (`jobs.ftl`, `pick.ftl`, `trash.ftl`, …). Every language has the same files and the same keys.
  The build embeds them (`include_str!`, the `AREAS` list in `crates/rf-ui/src/i18n.rs`): nothing is
  read from the disk at run time.
- `ui.ftl` holds **the window's words without arguments**: menu items, buttons, labels,
  placeholders, tooltips, the names screen readers hear. Each key is a property of the Slint global
  `Tr` (`crates/rf-ui/ui/tr.slint`); a screen says `Tr.<key>` (`Tr.command-new-folder` shows
  `command-new-folder`). Rust fills every property of every window as it is made
  (`ui_bridge::speak`), in the language of the run.
- `screen.ftl` holds **the window's words with a name, a number or a key** in them ("Recently
  Finished (3)", "Select a.txt"). Rust makes them (`words.rs`) and gives them to the window as a
  property or a field of a model. A `.slint` file never joins words itself.
- The other files hold what Rust says: the status line, notices, job lines, errors, the dialogs'
  messages (`words.rs`, `format.rs`).
- The Windows installer's words are in `installer/windows/racoon-finder.iss`, `[CustomMessages]`
  (see `installer/windows/README.md`).

## How a message is written

- **A key is `area-meaning`**: lowercase words joined by `-` (`job-panel-pause`, `status-items`,
  `error-not-found`), the same in every language. One key per meaning: the same Korean word with
  two meanings has two keys (`command-properties`, the app's Properties window, and
  `column-attributes`, the column; `job-panel-resume` and `common-continue` are both 계속).
- **Numbers and names are arguments**: `{ $name }`, `{ $count }`. A count is a Fluent number, so a
  plural is a selector: `{ $count -> [one] 1 item *[other] { $count } items }`. Use the plural
  categories of your language (CLDR: `zero`, `one`, `two`, `few`, `many`, `other`). A size or a date
  comes as the text it shows.
- **A sentence is one message**, never put together from pieces of another language. What differs by
  the work of a job or the kind of an item is a selector on an argument (`$work`, `$kind`, `$place`)
  with `*[other]` as the general case.
- **`$os`** (`windows`, `macos` or `other`) is given to every message without the caller passing it.
  Use it where the systems name things differently: "Recycle Bin" on Windows and "Trash" elsewhere,
  "Put Back", "Get Info in Finder", "Exit"/"Quit".
- **Arguments named `ko-…`** are for Korean alone (`$ko-final` chooses 이 or 가 after a name). Other
  languages leave them out; every other argument is the same in every language.
- A message of `ui.ftl` takes no argument but `$os`. No message starts or ends with white space.
- **English style**: menus, menu items, buttons and the parts of a segmented choice are in title case
  on every system ("Show Hidden Files", "Date Modified", "Size All Columns to Fit"); check boxes,
  placeholders, notices and sentences in sentence case ("Ignore case", "Do this for the rest"), as
  the Windows and macOS guidelines write them. Where a message names a menu, an item or a button
  ("View ▸ Layout ▸ Dual Pane", "Open Details in Recently Finished", "choose Cancel"), it says the
  title exactly as the window shows it.
- The names of the languages in View ▸ Theme are written in their own language in every file
  (`언어: 한국어`, `Language: 한국어`).
- **Room**: the smallest window is 900 × 560, and the largest look is View ▸ Theme ▸ Density: Roomy
  with Text Size: 130 %. Prefer a shorter word to a wider control. English needed "Regex" in the
  pattern window and "Do this for the rest" in the conflict window for that.

## A missing translation

A key a language lacks shows in English; a key no language has shows as the key itself. A debug build
notes either on stderr (`Localizer::text`). The tests below require every language to have every
key, so a missing one is a failing test, not a silent English word.

## Checks

```sh
cargo test -p rf-ui i18n            # the language tests (crates/rf-ui/src/i18n.rs)
cargo test -p rf-ui every_window    # every window, the tray icon too, gets all its words
cargo test -p rf-ui --test ui_smoke in_both_languages   # the View menu and the dialogs' rows
                                    # in Korean and English, at 900 x 560 and the largest look
```

What they hold:

- every file parses, every language has the same keys and the same arguments (but `ko-…` and
  `$os`), every message formats on every system with no Fluent error and no isolation marks, every
  area file is in `AREAS`, every key the Rust code asks for exists;
- `no_hangul_string_literal_outside_tests` and `no_slint_file_holds_a_hangul_string_literal`: no
  Korean word is written in Rust (outside tests and two named test fixtures) or in any `.slint`
  file; the words are in the `.ftl` files;
- `the_window_s_words_and_ui_ftl_are_one_to_one`: the properties of `Tr` and the keys of `ui.ftl`
  are the same, in every language, and each is shown somewhere (the build also reads `tr.slint`
  strictly: one `in property <string> key;` per line, no value);
- `every_window_is_made_with_its_words`: a window is made only by its maker in `ui_bridge`, which
  fills its words (a Slint global is per window);
- `english_menus_are_in_title_case`: every menu title of the screens, on every system;
- `the_menus_the_messages_name_are_titled_so` and `every_menu_name_in_an_english_message_is_listed`:
  a menu or menu item an English message names is listed in `NAMED_IN_MESSAGES` with its `Tr` keys,
  and the English and the Korean message say its title. The second test knows the titles the screens
  give their menus and items (`title:`, `titles:`) and the names already in `NAMED_IN_MESSAGES`; a
  dialog's button (a `text:`) it knows only once someone has listed it there, so when a message names
  a button, add the button to the list yourself. It finds a known title of two words or more anywhere
  in a message, and a one-word title capitalized inside a sentence; a one-word title at the start of
  a sentence it cannot tell from an ordinary word, so name such a title with a path (" ▸ ") or check
  it by eye;
- the fit tests measure with the testing backend's text, which is narrower than a real font's, and the
  menus they measure are the ones Slint draws itself, which only Linux shows: on Windows and macOS the
  same menus are OS menus, which the OS places and sizes. Look at the window too: seed the settings
  with `language = "en"` (or choose View ▸ Theme ▸ Language: English and restart), open the window
  at 900 × 560 with the largest look, and under Linux take shots with Xvfb
  (`SLINT_BACKEND=winit-software`). Every menu and sub-menu, the picker, the conflict window,
  the confirmations, the properties window, the pattern window and the job panel with a job, and
  the windows no English shot has seen yet: the error question (ask on each copy or move error), the
  failures window, the recovery window, the preflight, the note while the jobs stop at the end ("Stopping
  the jobs…") and the New Folder name window.

The tests never change the language of the run (it stays Korean in every test, and `i18n::init` is
called only by the app's `main`); a test of another language makes a `Localizer` of its own and fills
a window with `ui_bridge::speak_in`.

## The language of the run

`settings.toml` says `language = "system" | "ko" | "en"` (the items "Language: …" at the end of
View ▸ Theme write it; there is no Language sub-menu); with `system` the app speaks Korean when the
system's locale is Korean and English otherwise (`i18n::pick`). It is chosen once, before any window:
a change takes effect at the next start, and the window says so in the words of the language chosen.
Switching without a restart is the P1 part of I18N-01, not in this version.

## A new language

1. A folder `crates/rf-ui/i18n/<code>/` with every area file and every key (copy `en/` and
   translate). Keep the comments that say what an argument is.
2. In `crates/rf-ui/src/i18n.rs`: a `Lang` variant with its `code()`, in `Lang::ALL`; its files in
   `area!` / `AREAS`; and a rule in `pick` for the locales that choose it (and which language a
   locale of no listed language gets: English today).
3. A `LanguageChoice` variant in `settings.rs` (its name in `settings.toml`), and the item in View ▸
   Theme (`view-language-<code>` in every `ui.ftl` and `tr.slint`, the item in `view-menu.slint`,
   `language_number` / `language_of` in `controller/persist.rs`).
4. The installer: an entry in `[Languages]` and a line of each `[CustomMessages]`.
5. Run the checks, look at the window, and add the language's manual checks to
   `docs/ux/keyboard.md` ("언어").

## 1. 개요

### 1.1 한 줄 요약

Racoon Finder는 Windows 탐색기와 macOS Finder를 대체하는 오픈소스 듀얼 패널 파일 관리자다. Directory Opus 수준의 기능을 무료로, 가능한 한 가볍고 빠르게 제공한다.

### 1.2 배경

- **탐색기와 Finder의 한계.** 창 하나에 폴더 하나만 보이고, 대량 복사가 느리며, 복사 대기열·검증·재개가 없다. 압축, 사진/PDF 보기, FTP·클라우드 접속, 일괄 이름 변경, 폴더 비교 같은 일은 별도 앱을 설치해야 한다.
- **기존 대안의 공백.** Directory Opus는 기능이 가장 풍부하지만 유료이고 Windows 전용이다. Total Commander는 Windows 전용 셰어웨어, ForkLift와 Path Finder는 macOS 전용 유료 앱이다. Double Commander는 오픈소스 크로스플랫폼이지만 UI와 사용 경험이 탐색기·Finder와 거리가 있다. Windows와 macOS에서 같은 경험을 주는 무료 고급 파일 관리자는 없다.
- **한국 사용자 고유의 문제.**
  - Windows에서 만든 ZIP의 한글 파일명(CP949)이 macOS나 다른 압축 프로그램에서 깨진다.
  - macOS에서 넘어온 파일명은 자모가 분리(NFD)되어 Windows에서 "ㅎㅏㄴㄱㅡㄹ"처럼 보인다.
  - FTP 서버의 CP949 파일명이 깨진다.

### 1.3 목표

| ID | 목표 | 측정 기준 |
|---|---|---|
| G1 | Windows 탐색기 완전 대체 | 5.15의 진입 경로 커버리지 표에서 "Racoon Finder" 항목 100% 동작 |
| G2 | Directory Opus 핵심 기능 동등 | 6장 대응표의 P0 항목 100% 구현 |
| G3 | 가장 가볍고 빠른 파일 관리자 | 7.1 성능 목표 전 항목 달성 |
| G4 | 데이터 무결성 | 복사·이동·동기화·이름 변경 중 데이터 손실 버그 0건 |
| G5 | 흔적 없는 설치와 삭제 | 클린 VM 설치→사용→삭제 후 차이 0 (INST-07) |
| G6 | 두 OS에서 같은 경험 | 같은 기능 집합, 같은 설정 형식, Windows 백업을 macOS에서 복원 가능 |

### 1.4 비목표 (1.0 기준)

- **사용자 자동화.** 툴바·메뉴 편집, 명령어 언어, 스크립팅, 단축키 재배정은 넣지 않는다. 툴바는 표시/숨김만 가능한 고정 구성이다.
- **셸 교체.** 바탕화면, 작업 표시줄, 시작 메뉴, Dock은 대체하지 않는다.
- **파일 열기/저장 대화상자 대체.** OS가 허용하지 않는다.
- **macOS Finder 프로세스 대체.** Finder는 그대로 실행되고, 폴더 열기 요청만 가져온다.
- **지원하지 않는 플랫폼.** Intel Mac, Windows 10 이하, macOS 14 이하, Linux.
- **상시 클라우드 동기화 클라이언트 역할.** 원격 저장소는 탐색과 전송만 한다.
- **편집기 기능.** 이미지·문서 편집, Office→PDF 변환(LibreOffice가 필요), HWP 변환은 넣지 않는다.
- **RAR 압축 만들기.** 독점 형식이라 압축 해제만 지원한다.
- **수익화.** 텔레메트리, 사용 통계 수집, 계정 가입, 유료 기능은 없다.

## 2. 대상 사용자와 사용 시나리오

### 2.1 페르소나

| 페르소나 | 설명 | 핵심 요구 |
|---|---|---|
| 파워 유저 | 개발자·디자이너·사무직. 매일 수천 개 파일을 다루고 Windows와 Mac을 같이 쓴다. 키보드 위주로 작업한다. | 듀얼 패널, 빠른 복사, 원격 접속, 일괄 이름 변경 |
| 이주자 | Directory Opus나 Total Commander 사용자. 유료 라이선스가 부담되거나 Mac에서도 같은 도구를 원한다. | 익숙한 기능 대응, 폴더별 보기 설정, 동기화 |
| 일반 사용자 | 탐색기보다 빠른 복사, 압축, 사진 보기를 별도 앱 없이 쓰고 싶다. | 쉬운 기본값, 미리보기, 한글 파일명 문제 해결 |

### 2.2 핵심 시나리오

| ID | 시나리오 | 관련 요구사항 |
|---|---|---|
| S1 | **다운로드 정리.** 왼쪽에 다운로드 폴더, 오른쪽에 프로젝트 폴더를 연다. 사진은 스페이스바로 확인하고, 끌어다 놓아 옮긴다(기본 동작 이동). 길게 눌러 '이동…'을 고르고 모달에서 다른 폴더를 지정하기도 한다. | LAY, DND, PICK, VIEW-01 |
| S2 | **대용량 백업.** 외장 SSD로 50GB 복사를 걸고 NAS 복사를 추가로 대기열에 넣는다. 서로 다른 디스크라 병렬로 진행되고, 끝나면 해시 검증 결과가 나온다. | XFER |
| S3 | **한글 ZIP 받기.** 메일로 받은 ZIP을 더블클릭하면 폴더처럼 열리고 한글 파일명이 정상으로 보인다. 필요한 파일만 끌어서 꺼낸다. | ARC-01, ARC-06 |
| S4 | **서버 배포.** SFTP에 접속해 로컬 폴더와 원격 폴더를 비교한다. 바뀐 파일만 미리보기로 확인한 뒤 업로드한다. | REM, SYNC |
| S5 | **사진 정리.** EXIF 촬영일 기준으로 `2026-10-22_001.jpg` 형식으로 일괄 이름을 바꾸고, HEIC를 JPG로 일괄 변환한다. | REN, CONV-02 |
| S6 | **다른 앱에서 폴더 열기.** 브라우저의 "폴더 열기"나 바탕화면 폴더 더블클릭 시 탐색기 대신 Racoon Finder가 150ms 안에 열린다. | WINX |
| S7 | **PC 이전.** Windows에서 만든 설정 백업을 새 Mac에서 복원하면 테마, 즐겨찾기, 라벨, 연결 프로필이 그대로 넘어온다. | BAK |
| S8 | **삭제.** 앱을 제거하면 레지스트리와 파일 흔적이 남지 않고, 폴더 열기는 탐색기로 돌아간다. | INST |

## 3. 제품 원칙

기능 간 우선순위가 충돌할 때 아래 순서로 판단한다.

1. **데이터는 절대 잃지 않는다.** 파괴적인 작업은 미리보기, 확인, 되돌리기, 휴지통 중 하나 이상을 거친다.
2. **가볍고 빠르게.** 기능을 추가해도 7.1의 시작 시간·메모리 예산을 넘기지 않는다. 무거운 구성요소(FFmpeg)는 선택 설치로 둔다.
3. **흔적 없이.** OS에 가하는 변경은 모두 기록하고, 삭제할 때 원래대로 되돌린다.
4. **OS와 자연스럽게.** 셸 메뉴, 썸네일, 클립보드, 드래그 앤 드롭을 OS 표준 방식으로 주고받는다.
5. **키보드로 모든 것을.** 모든 기능을 키보드만으로 실행할 수 있어야 한다.
6. **두 OS, 같은 경험.** 기능과 설정은 같고, 단축키와 관례만 각 OS를 따른다.

### 4.2 배포 형태

| 형태 | 플랫폼 | 설명 |
|---|---|---|
| 설치형 | Windows | 사용자 단위 설치가 기본이다(관리자 권한 불필요, `%LOCALAPPDATA%\Programs\RacoonFinder`). 전체 사용자 설치도 선택할 수 있다. 설치 도구로 Inno Setup을 제안한다([Q7](#13-열린-질문)). |
| 포터블 | Windows | ZIP 하나로 배포한다. 레지스트리를 쓰지 않으며, 탐색기 대체·상주·파일 연결 기능은 꺼진다(INST-06). |
| DMG | macOS | Applications 폴더로 끌어서 설치하는 표준 방식이다. |
| 패키지 관리자 | 공통 | winget, Scoop, Homebrew cask(`zap` 포함). P1 |

### 4.3 서명, 공증, 업데이트

- **코드 서명.**
  - Windows: Authenticode 서명. SignPath Foundation(오픈소스 무료 서명)을 우선 신청하고, 안 되면 Azure Trusted Signing을 쓴다.
  - macOS: Apple Developer ID 서명과 공증(연 $99).
  - 서명되지 않은 빌드는 릴리스하지 않는다.
- **업데이트.**
  - GitHub Releases에서 새 버전을 확인한다. 기본으로 켜져 있고 끌 수 있다.
  - 새 버전이 있으면 알림을 띄우고, 사용자가 한 번 클릭하면 설치한다.
  - 내려받은 파일은 ed25519 서명을 검증한 뒤에 적용한다.
  - 채널은 stable과 beta 두 가지다.
- **포터블 업데이트.** 새 버전 알림만 띄운다. 교체는 사용자가 직접 한다.

### 4.4 라이선스

- 프로젝트 코드는 GPL-3.0이다. 의존성 라이선스는 8.5에서 관리한다.
- unRAR 소스는 GPL과 호환되지 않으므로 쓰지 않는다. RAR 해제는 libarchive를 사용한다.

## 5. 기능 요구사항

### 우선순위 정의

| 등급 | 의미 |
|---|---|
| **P0** | 1.0 출시 필수. 하나라도 빠지면 출시하지 않는다. |
| **P1** | 1.0 포함 목표. 일정이 밀리면 1.1로 넘길 수 있다. 넘기는 결정은 M5 진입 시점에 한다. |
| **P2** | 1.x 이후. |

요구사항 ID는 `영역-번호` 형식이다. 각 ID는 10장 로드맵의 마일스톤에 배정된다.

| PICK-01 | **진입 경로.** (a) 파일을 우클릭하고 '이동…' 또는 '복사…' 선택, (b) 파일을 **길게 눌러** 열린 메뉴에서 같은 항목 선택, (c) 메뉴 막대·툴바의 '이동…/복사…' 버튼, (d) 단축키. | P0 |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| XFER-01 | **작업 대기열.** 복사·이동·삭제·압축·변환·업로드는 모두 작업(Job)으로 실행된다. 작업 패널에 진행률, 속도, 남은 시간, 현재 파일, 속도 그래프를 보여 준다. 일시정지, 재개, 취소, 순서 변경이 가능하다. | P0 |

| XFER-03 | **대용량 파일.** 읽기와 쓰기를 겹치는 비동기 이중 버퍼 파이프라인을 쓴다. 임계값(기본 256MB) 이상의 파일은 캐시를 우회하는 I/O(Windows unbuffered I/O, macOS `F_NOCACHE`)로 처리하고, 버퍼 크기는 장치에 맞춰 자동으로 정한다. | P0 |

| XFER-05 | **빠른 경로.** 같은 볼륨 이동은 이름 변경으로 즉시 끝낸다. APFS 같은 볼륨 복사는 `clonefile`, ReFS/Dev Drive는 블록 복제, SMB는 서버 측 복사(오프로드)를 쓴다. | P0 |
| XFER-06 | **충돌 처리.** 선택지는 묻기(양쪽 크기·날짜·미리보기 비교), 덮어쓰기, 건너뛰기, 더 새 파일만 덮어쓰기, 크기가 다를 때만 덮어쓰기, 자동 이름 변경이다. "나머지에 모두 적용"을 지원한다. | P0 |

## 7. 비기능 요구사항

### 7.1 성능

**측정 기준 환경.** Windows: 8코어 x64 CPU, 16GB RAM, NVMe SSD 2개. macOS: Apple M1, 16GB RAM. 릴리스 빌드에서 측정한다.

| PERF-05 | 메모리 | 유휴(창 1개, 패널 2개, 썸네일 없음) 80MB 이하. 10만 개 항목 폴더를 볼 때 250MB 이하 |

### 7.2 안정성과 데이터 무결성

| ID | 요구사항 |

### 8.3 데이터 흐름

**폴더 목록**
1. UI가 `list(VPath)`를 요청한다.
2. 공급자가 항목을 일정 크기 묶음(예: 2,000개)으로 스트리밍한다. Windows는 `FindFirstFileExW`(large fetch), macOS는 `getattrlistbulk`를 쓴다.
3. 뷰모델이 묶음을 받는 대로 반영하고, 화면에 보이는 행만 그린다(가상화).
4. 변경 감시(`ReadDirectoryChangesW`, FSEvents) 이벤트가 오면 차이만 적용한다.

**파일 작업**
1. UI 명령(복사, 이동 등)이 작업 명세(JobSpec)가 된다.
2. 계획 단계에서 파일을 열거하고, 충돌을 검사하고, 공간과 파일 시스템 제약을 확인한다.
3. 스케줄러가 작업을 장치별 대기열에 배정한다.
4. 실행하면서 단계마다 저널에 기록한다.
5. 진행 이벤트를 UI로 보낸다.
6. 끝나면 완료 보고를 만들고 되돌리기 기록을 남긴다.

**OS 변경**
- 레지스트리, 기본값, 로그인 항목 등의 변경은 모두 `rf-ledger` API를 거친다. 이 API는 바꾸기 전 값을 기록하고, 클린 삭제 때 역순으로 되돌린다.

## 15. 용어집

| 용어 | 뜻 |
|---|---|
| 패널 | 폴더 내용을 보여 주는 영역. 듀얼 패널은 두 패널을 나란히 놓은 배치 |
| 활성 패널 | 키보드 입력과 명령이 적용되는 패널 |
| VFS | 가상 파일 시스템. 로컬, 압축 파일, 원격, 가상 폴더를 같은 방식으로 다루는 계층 |
| 작업(Job) | 복사·이동·압축·변환처럼 대기열에서 실행되는 파일 작업 단위 |
| 저널 | 작업 진행 상태를 디스크에 기록한 것. 충돌 후 재개에 쓴다 |
| 변경 원장 | 앱이 OS에 가한 변경과 이전 값을 기록한 것. 클린 삭제에 쓴다 |
| 상주 모드 | 창이 없어도 트레이·메뉴 막대에서 대기해 폴더 열기를 즉시 처리하는 모드 |

| 컬렉션 | 여러 위치의 파일을 참조로 모아 두는 가상 폴더 |
| PICK 모달 | 이동·복사 등의 대상 위치를 고르는 앱 내부 팝업 창 |
| NFC / NFD | 유니코드 정규화 형식. NFD는 한글 자모가 분리된 형태(주로 macOS에서 생김)이고 NFC는 완성형이다 |

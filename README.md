# Racoon-Finder

Windows 11과 macOS 15에서 쓰는 듀얼 패널 파일 관리자입니다. 아직 개발 중입니다.

## 데모 실행

개발 중인 데모를 내 PC에서 직접 써 볼 수 있습니다. 지금 데모는 **0.3.0**(데모 3판)입니다. `main`과 `feat/…` 브랜치에
커밋이 올라올 때마다 GitHub Actions의 **Demo build**가 OS별 실행 파일을 만듭니다. 설치 프로그램은 아직 없고, 서명·공증을
하지 않은 데모라서 처음 열 때 OS가 경고합니다.

> **주의:** 데모는 진짜 파일을 옮기고 지웁니다. 처음에는 연습용 폴더에서 써 보세요. 예를 들어 바탕 화면에
> `연습` 폴더를 만들고 아무 파일이나 복사해 넣은 뒤, 그 안에서만 옮기고 지워 봅니다. 3판의 다른 앱과 주고받는
> 끌어 놓기는 실제 PC에서 처음 써 보는 기능이라, 탐색기·Finder와 끌어 주고받을 때도 연습용 파일로 먼저 해 봅니다.

### 내려받기

버전 태그가 붙은 데모(0.3.0부터)는 저장소의 **Releases**에서도 같은 네 파일을 내려받을 수 있습니다
([v0.3.0](https://github.com/doguri25/Racoon-Finder/releases/tag/v0.3.0)). 개발 중인 최신 빌드는 아래처럼 Actions에서 받습니다.

1. GitHub에 로그인합니다. Actions 산출물은 로그인해야 내려받을 수 있습니다.
2. 이 저장소의 **Actions** 탭 → 왼쪽 목록의 **Demo build** → 초록 체크 표시가 붙은 최근 실행을 엽니다. 0.3.0 데모는
   `feat/m1-core` 브랜치(합친 뒤에는 `main`)의 실행입니다. 실행 제목 옆의 브랜치 이름으로 고릅니다.
3. 아래쪽 **Artifacts**에서 내 PC에 맞는 파일을 내려받습니다. 산출물은 30일 동안 남아 있습니다. 세 OS의 파일은 같은
   실행에서 함께 만들어집니다: Windows는 zip, macOS는 ad-hoc 서명한 `.app`을 담은 zip, Linux는 tar.gz입니다.

| PC | 파일 |
| --- | --- |
| Windows 11 (대부분의 PC) | `RacoonFinder-demo-windows-x64.zip` |
| Windows 11 ARM (Snapdragon 등) | `RacoonFinder-demo-windows-arm64.zip` |
| Apple 실리콘 Mac (M1 이후) | `RacoonFinder-demo-macos-arm64.zip` |
| Linux x64 (개발용) | `RacoonFinder-demo-linux-x64.tar.gz` |

Windows에서 어느 쪽인지 모르겠으면 설정 → 시스템 → 정보의 "시스템 종류"를 봅니다("x64 기반 프로세서" 또는
"ARM 기반 프로세서"). Intel Mac용 데모는 아직 없습니다. 압축 파일 안의 `데모-안내.txt`에 같은 안내가 짧게 들어
있습니다.

### Windows 11

1. 내려받은 zip을 오른쪽 클릭 → **모두 압축 풀기**. zip 안에서 바로 실행하지 마세요(아래 데이터 설명 참고).
2. 풀린 폴더의 `racoon-finder.exe`를 실행합니다.
3. "Windows의 PC 보호" 창이 뜨면 **추가 정보** → **실행**을 누릅니다. 서명하지 않은 데모라서 나오는 경고입니다.

설정과 작업 기록은 `racoon-finder.exe` 옆의 `data` 폴더에만 저장됩니다. 같은 폴더의 빈 `portable` 파일이 그렇게
하라는 표시라서, 지울 때는 앱을 끄고 폴더를 통째로 지우면 끝입니다.

### macOS 15

1. 내려받은 zip을 엽니다(Safari는 알아서 풀기도 합니다). `Racoon Finder.app`을 원하면 응용 프로그램 폴더로 옮깁니다.
2. 앱을 두 번 누릅니다. 공증하지 않은 데모라서 macOS가 열지 않고 경고 창을 띄웁니다. **완료**를 눌러 닫습니다.
3. **시스템 설정 → 개인정보 보호 및 보안**의 아래쪽에서 **그래도 열기**를 누르고, 한 번 더 묻는 창에서도
   **그래도 열기**를 누른 뒤 암호(또는 Touch ID)를 넣습니다. 그다음부터는 그냥 열립니다. (macOS 14 이하에서는 앱을
   Control-클릭(오른쪽 클릭) → **열기**로도 됩니다.)
4. 그래도 "손상되었기 때문에 열 수 없습니다"처럼 막히면 터미널에서 앱이 있는 폴더로 가서 실행한 뒤 다시 엽니다.

   ```sh
   xattr -dr com.apple.quarantine "Racoon Finder.app"
   ```

5. 데스크탑·문서·다운로드 폴더에 접근해도 되는지 물으면 **허용**을 누릅니다. 새 데모를 받을 때마다 다시 물을 수
   있습니다.

설정과 작업 기록은 `~/Library/Application Support/io.github.doguri25.RacoonFinder`에 저장됩니다. 지울 때는 앱과 이
폴더, 그리고 `~/Library/Caches/`와 `~/Library/Logs/` 아래의 같은 이름 폴더를 지웁니다.

### 데모로 해 볼 수 있는 것

0.1에서 하던 것(두 패널과 탭, 경로 줄, 즐겨찾기·드라이브·폴더 트리, 새 폴더·이름 바꾸기·휴지통·영구 삭제, 위치를 고르는
복사…·이동…, 앱 안의 끌어 놓기, 같은 이름 처리, 되돌리기·다시 실행, 작업 패널과 끊긴 작업 복구, 테마와 설정 기억)과
2판에서 더해진 것(아래 두 번째 목록)에, 3판에서 다른 앱과 주고받는 끌어 놓기와 Windows 메뉴가 더해졌습니다. 자세한
동작과 키는 [docs/ux/keyboard.md](docs/ux/keyboard.md)의 "끌어 놓기"와 "Windows 메뉴와 macOS 공유" 절에 있습니다.

#### 3판(0.3)에서 더해진 것

- **다른 앱에서 끌어 오기:** 탐색기·Finder·바탕 화면 등에서 파일과 폴더를 목록의 폴더 행, 목록의 빈 곳, 탭, 트리의
  행에 끌어 놓습니다. 앱 안의 끌기처럼 놓을 곳이 강조되고 커서 옆에 "이동 → 폴더"·"복사 → 폴더"나 놓을 수 없는
  까닭이 뜹니다. 이동도 복사도 앱의 작업이 합니다(이름이 겹치면 묻고, 작업 패널에 보이고, 되돌릴 수 있습니다). 이동은
  복사를 마친 항목만 앱이 원본을 지우고, 끌어 온 앱에는 원본을 먼저 지우게 할 답을 주지 않습니다. 대화상자나 빠른 보기가
  떠 있는 동안에는 받지 않습니다. Linux(X11, 개발용)는 놓은 파일을 활성 패널의 폴더로 늘 복사합니다.
- **다른 앱으로 끌어내기(Windows·macOS):** 자세히의 행이나 아이콘·목록 보기의 항목을 창 밖으로 끌고 나가면 그때부터
  OS의 끌기가 되어 탐색기·Finder·바탕 화면·Dock의 휴지통·브라우저의 파일 올리기·메일 첨부에 놓을 수 있습니다. 받는
  앱이 OS 규칙대로 옮기거나 복사하고, 앱은 끌어낸 뒤 아무것도 지우지 않습니다. 창 밖으로 나갔다가 앱 창으로 돌아와
  놓으면 앱 안의 끌기처럼 놓입니다.
- **놓을 때의 동작:** 보조키가 정합니다. Windows는 탐색기처럼 Ctrl이 복사·Shift가 이동, macOS는 Finder처럼 ⌥이
  복사·⌘이 이동, Linux는 Ctrl이 복사·Shift가 이동입니다. 링크 키(Windows Alt, macOS ⌥⌘, Linux Ctrl+Shift)는 "링크
  만들기는 아직 없습니다"를 보이고 받지 않습니다. 보조키가 없으면 보기 ▸ 설정의 "끌어 놓기: 이동"(기본값)·"복사"·
  "OS 방식"(같은 드라이브면 이동, 다른 드라이브면 복사)·"매번 묻기"(놓은 자리에 여기로 이동·여기로 복사·취소 메뉴.
  끌기가 허용하지 않는 것은 빠집니다)를 따릅니다. 탐색기에서 오른쪽 버튼으로 끌어 놓아도 이 메뉴가 뜹니다. 커서 옆 문구와 커서 모양은 키를 누르거나 떼면
  마우스를 움직이지 않아도 바로 바뀝니다.
- **머무르면 열기와 자동 스크롤:** 끄는 동안 폴더 행, 다른 탭, 트리의 닫힌 폴더에 1초 머물면 그곳이 열리고 끌기는
  이어집니다. 목록과 트리의 끝(목록 보기는 왼쪽·오른쪽 끝)에 머물면 끝까지 굴러갑니다.
- **옮긴 뒤 되돌리기 알림:** 끌어서 옮기면 5초 동안 "항목 N개를 옮겼습니다 [되돌리기]"가 뜹니다. 보기 ▸ 설정의
  "끌어서 옮긴 뒤 되돌리기 알림"으로 끄면 뜨지 않고, Ctrl+Z(macOS ⌘Z)로는 여전히 되돌립니다.
- **Windows 메뉴:** Shift+오른쪽 클릭과 Shift+F10이 탐색기의 오른쪽 클릭 메뉴(Windows 11 탐색기의 "더 많은 옵션
  표시")를 띄웁니다: "보내기"·"연결 프로그램" 하위 메뉴와 7-Zip·Git 같은 셸 확장의 항목이 있습니다. 앱 메뉴 맨 아래의
  "더 많은 옵션 표시"도 같은 메뉴를 띄우고, 보기 ▸ 설정의 "오른쪽 클릭에 Windows 메뉴 바로 띄우기"를 켜면 오른쪽
  클릭과 메뉴 키가 앱 메뉴 대신 바로 띄웁니다. 그 메뉴의 이름 바꾸기·삭제·잘라내기·복사·붙여넣기는 앱 메뉴의 같은
  명령과 똑같이 앱이 합니다(이름 입력 창, 작업 엔진의 휴지통, 앱의 클립보드). 그래서 휴지통으로 가는 삭제와 이름
  바꾸기는 되돌릴 수 있고, Shift를 누른 채 고른 삭제(Shift+삭제)는 확인 창을 거친 뒤 영구 삭제라 되돌릴 수 없습니다.
- **공유(macOS):** 항목 메뉴의 "공유…"가 macOS의 공유 메뉴(AirDrop, 메일, 메시지 등)를 띄웁니다.

#### 2판(0.2)에서 더해진 것

- **화면 배치:** 듀얼 패널 켜기·끄기(F12, 끄면 한 패널 보기), 위아래로 나누기(Shift+F12), 두 패널 사이 분할선
  끌기(두 번 누르면 반반), 패널 바꾸기, 같은 폴더를 반대편에 열기(F9), 한쪽에서 폴더를 옮기면 반대편도 따라가는 탐색
  동기화(Shift+F9), 폴더 트리 보이기·숨기기. 배치는 다음 실행 때 그대로 돌아옵니다. 위아래로 나누기는 창이 900×560이면
  패널마다 3줄쯤 보이니 큰 창에서 씁니다.
- **탭:** 탭 메뉴(닫기, 다른 탭 닫기, 오른쪽 탭 닫기, 복제, 고정, 반대 패널로 옮기기), 닫은 탭 다시 열기, 끌어서 순서
  바꾸기와 반대 패널로 옮기기, 가운데 버튼으로 닫기. 고정한 탭은 다른 폴더로 갈 때 새 탭을 엽니다.
- **주소창:** 경로 조각 옆 `›`로 하위 폴더 목록을 열고, 경로를 칠 때는 하위 폴더 이름을 자동 완성합니다(Tab).
  `file:` 주소를 붙여넣어도 그 폴더로 갑니다.
- **보기와 열:** 자세히·목록·아이콘(작게·보통·크게; 종류별 아이콘이고 썸네일은 아직 없음). 자세히의 열(크기, 수정한 날짜,
  만든 날짜, 종류, 확장자, 속성)을 보이고 숨기고, 끌어서 순서와 너비를 바꾸고, 글자에 맞춥니다. 2차 정렬과 "폴더 먼저",
  파일 확장자 숨기기. 보기는 폴더마다 기억하고 "하위 폴더에 적용"도 할 수 있습니다. 새로 고침(F5).
- **선택 도구:** 툴바의 **선택** 메뉴에서 모두 선택, 선택 해제, 선택 반전, 패턴으로 선택(`*.jpg;*.png` 같은 와일드카드나
  정규식), 같은 확장자 선택. 이 폴더에서 거르기 칸은 이름으로 목록을 좁힙니다.
- **미리 보기·빠른 보기:** 미리 보기 패널(Alt+P, macOS ⇧⌘P)과 빠른 보기(Space)가 이미지, 글(인코딩을 알아서 고름),
  폴더의 항목 수를 보입니다. 큰 파일도 창을 멈추지 않고, OneDrive·iCloud의 온라인 전용 파일은 내려받지 않습니다.
- **클립보드:** 탐색기·Finder와 파일을 주고받는 복사·잘라내기·붙여넣기(Ctrl+C·X·V, macOS ⌘C·⌘V, 옮겨 붙이기 ⌥⌘V).
  잘라낸 항목은 흐리게 보이고, 이름이 겹치면 `파일 (2).txt`로 붙이고, 붙여넣은 항목은 선택됩니다. 클립보드에 파일이
  없으면 메뉴의 붙여넣기가 꺼집니다. 경로 복사(Ctrl+Shift+C, macOS ⌥⌘C)는 전체 경로·이름만·따옴표 포함·UNC·슬래시·파일
  URL 여섯 형식입니다.
- **속성·체크섬:** 속성(Alt+Enter, macOS ⌘I)이 크기(폴더는 안을 모두 세어), 날짜, 속성, 링크 대상을 보이고, MD5·SHA-1·
  SHA-256·BLAKE3·xxHash3-64 체크섬을 계산해 복사하거나 붙여넣은 값과 비교합니다.
- **연결 프로그램·터미널·OS 속성 창:** 항목 메뉴의 "연결 프로그램으로 열기…", Windows의 "관리자 권한으로 실행", "터미널에서
  열기"(Shift+F4), "OS 속성 창 열기"(탐색기 속성 창, Finder 정보 가져오기).
- **작업 보고·알림·트레이:** 작업 패널의 "최근 완료"(복사 수, 건너뜀, 오류, 평균 속도, 걸린 시간)와 "로그 저장…". 10초
  넘게 걸린 작업이 창이 뒤에 있을 때 끝나면 OS 알림을 보냅니다. 작업 중에 창을 닫으면 "트레이에서 계속"(macOS는 메뉴
  막대)을 고를 수 있고, 앱을 다시 실행하면 새 창 대신 숨은 창이 돌아옵니다.
- **키보드:** 단축키를 OS별로 정했습니다. Windows는 파일 탐색기, macOS는 Finder와 같은 키이고, 듀얼 패널에만 있는 동작은
  두 쪽 모두 쓰지 않는 키를 받았습니다. 툴바 버튼의 툴팁과 메뉴 항목에 키가 보이고, 마우스로 하는 일은 거의 모두
  키보드로도 닿습니다(항목 메뉴는 메뉴 키, Linux는 Shift+F10도, macOS ⌃↩. 폴더 트리와 작업 패널은 F6). 한 열만의
  너비는 키로 정하지 않고 "모든 열 너비 맞추기"(Ctrl+Shift+=, macOS ⌃⌘=)로 글자에 맞춥니다.

### 0.3.0에서 알아 둘 점

- **끌어 놓기의 기본 동작은 이동입니다.** 보조키 없이 끌어 놓으면 다른 드라이브(USB 등)에서 끌어 온 것도 옮깁니다(끌어
  온 앱이 이동을 허용하지 않을 때만 복사). 복사가 끝난 뒤 앱이 원본을 지웁니다. 탐색기·Finder처럼 다른 드라이브에서는
  복사하려면 보기 ▸ 설정의 "끌어 놓기: OS 방식"을 고르거나, 놓을 때 Ctrl(macOS ⌥)을 누릅니다.
- **0.2에서 올릴 때:** 0.2의 설정 파일을 그대로 읽고, 새 설정은 기본값("끌어 놓기: 이동", 되돌리기 알림 켬, Windows 메뉴
  바로 띄우기 끔)으로 시작합니다.
- **Windows에서 끌어낸 동안과 Windows 메뉴가 떠 있는 동안:** 앱 창이 다시 그려지지 않습니다(그동안 OS의 루프가 돌고,
  창 라이브러리가 그리기를 미룹니다). 끌어낸 항목을 놓지 않고 앱 창으로 가져오면 커서 옆 문구, 놓을 곳의 강조,
  머무르면 열기, 자동 스크롤이 없습니다. 놓기는 되고, 끌기 그림 아래의 문구는 탐색기가 그려 보입니다.
- **macOS에서 끌어 오기:** 앱은 끌어 온 앱에 "이동"이라고 답하지 않습니다(그 앱이 원본을 먼저 지우지 않게). 그래서
  이동만 허용하는 앱에서 끈 것은 받지 않습니다. ⌃을 누른 채 끌면 금지 커서이고, 제목 막대 위에 놓은 파일은 활성 패널의
  폴더로 복사됩니다(위치와 보조키 없이).
- **앱 안의 오른쪽 버튼 끌기는 없습니다.** 창 라이브러리(Slint)의 끌기는 왼쪽 버튼으로만 시작합니다. 놓을 때마다 고르려면
  설정의 "끌어 놓기: 매번 묻기"를 씁니다. 탐색기에서 오른쪽 버튼으로 끌어 오는 것은 묻기 메뉴를 띄웁니다.
- **Windows 메뉴:** 셸 확장은 앱 안에서 돌기 때문에 잘못 만든 확장이 앱을 끝내거나 멈출 수 있습니다. Windows 11의 새
  메뉴에만 등록된 항목은 없을 수 있습니다(탐색기의 "더 많은 옵션 표시"와 같습니다). 폴더의 "열기"는 앱의 패널이 아니라
  탐색기 창으로 엽니다. 앱이 하지 않는 명령(속성, 보내기, 셸 확장 등)이 파일을 바꾸면 앱의 되돌리기에 남지 않습니다.
  "오른쪽 클릭에 Windows 메뉴 바로 띄우기"를 켠 동안에는 "연결 프로그램으로 열기…"와 "관리자 권한으로 실행"을 Windows
  메뉴 자신의 항목으로 합니다(앱의 메뉴가 뜨지 않고, 두 명령에는 키가 없습니다).
- **새 판의 zip을 새 폴더에 풀면(Windows):** 설정과 작업 기록은 `racoon-finder.exe` 옆의 `data` 폴더에 있으므로, 새
  폴더의 앱은 처음 실행처럼 빈 설정으로 시작합니다. 탭, 배치, 창 크기를 이어 쓰려면 두 앱을 모두 끈 뒤 예전 폴더의
  `data` 폴더를 새 폴더의 `racoon-finder.exe` 옆에 통째로 복사하고(새 폴더에 `data`가 이미 있으면 바꿉니다) 새 앱을
  실행합니다. macOS는 설정이 앱 밖(`~/Library/Application Support/…`)에 있어 앱만 바꾸면 이어집니다.
- **0.1에서 바로 올릴 때:** 끝나지 않은 작업을 모두 끝내거나 다음 실행의 복구 창에서 버린 뒤 새 판으로 바꾸세요. 0.1(또는
  2판 개발 중의 이전 빌드)은 복사를 되돌릴 때 휴지통에 넣지 못한 복사본을 평범한 영구 삭제 작업으로 지웠습니다. 그 작업이
  작업 기록에 끝나지 않은 채 남아 있다가 새 판의 복구 창에서 "다시 실행"을 고르면, 새 판의 복사본 지우기와 달리 복사본이
  그사이 바뀌었는지 다시 확인하지 않고 지웁니다.
- **Windows 알림의 보낸 이:** 설치 프로그램이 없어 앱이 Windows에 자기 이름을 등록하지 않으므로, 작업 완료 알림에는
  보낸 이로 "Windows PowerShell"이 보입니다.
- **macOS의 ⌘Q, 앱 메뉴의 종료, Dock의 종료:** 묻지 않고 앱을 끝냅니다. 창의 닫기 버튼과 같은 순서로 설정을 저장하고 진행
  중인 작업을 멈춘 뒤 끝나며, 멈춘 작업은 다음 실행의 복구 창에 나옵니다. 메뉴 막대로 숨긴 동안에도 같습니다. 작업이 도는
  중에 "끝낼까요?"를 묻고 "메뉴 막대에서 계속"을 고르려면 ⌘Q 대신 창의 닫기 버튼(숨긴 동안에는 메뉴 막대 아이콘의
  "끝내기")을 씁니다. (macOS가 앱을 끝내는 길에서는 묻는 창을 띄울 수 없습니다.)
- **macOS에서 숨은 창 되찾기:** 메뉴 막대로 숨긴 창은 Dock 아이콘을 누르거나 Finder에서 앱을 다시 열어도 돌아오지
  않습니다(macOS가 실행 중인 앱에 보내는 "다시 열기"를 지금의 창 라이브러리가 앱에 알리지 않습니다). 메뉴 막대 아이콘의
  "창 열기"(또는 아이콘 클릭)를 쓰거나, 터미널에서 `open -n "/Applications/Racoon Finder.app"`처럼 한 번 더 실행합니다.

### 실제 PC에서 손으로 확인할 것

자동 테스트는 Linux와 CI의 Windows·macOS 러너에서 돕니다. 실제 OS 창, 메뉴, 클립보드, 알림, 다른 앱과의 끌어 놓기가
걸린 일은 Windows 11과 macOS 15에서 손으로 확인합니다. 자세한 단계는 [docs/ux/keyboard.md](docs/ux/keyboard.md)의 각
절에 있고, 아래의 번호는 그 절의 "손으로 확인할 것" 번호입니다.

#### 먼저: 원본이 남는지

처음 세 줄은 파일을 잃는지에 걸린 일이라 가장 먼저 봅니다. macOS에서는 넷째 줄(투명한 뷰)을 먼저 봅니다. 그것이 안
되면 둘째 줄의 끌기가 앱의 받기에 오지 않습니다.

- [ ] **Windows, 탐색기에서 Shift를 누른 채 앱으로 끌어 이동:** 놓은 직후에도, 앱의 복사가 끝나기 전에는 탐색기 쪽
  원본이 그대로 있습니다(탐색기가 원본을 스스로 지우지 않습니다). 복사가 끝난 뒤 앱의 작업이 원본을 지웁니다. 큰
  파일(수 GB), 작은 파일 여러 개, 폴더 하나로 한 번씩. 탐색기가 원본을 먼저 지우면 데이터를 잃는 문제이니 바로 알려
  주세요. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 11번)
- [ ] **macOS, Finder에서 앱으로 끌어 이동(⌘을 누른 채, 그리고 키 없이 "끌어 놓기: 이동"으로):** 놓은 자리에서 끌기
  그림이 사라지고 Finder로 미끄러져 돌아가지 않습니다. 앱의 이동 작업이 도는 동안 Finder는 원본을 지우지 않고(Finder
  창에 그대로 있습니다), 복사가 끝난 뒤 앱의 작업이 원본을 지웁니다. 큰 파일, 작은 파일 여러 개, 폴더 하나로 한 번씩.
  매번 묻기로 놓으면 끌기 그림이 Finder로 돌아가고, 메뉴에서 고르기 전에는 원본이 그대로입니다. Finder가 원본을 먼저
  지우면 바로 알려 주세요. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 20번)
- [ ] **Windows·macOS, 앱에서 다른 앱으로 끌어낸 뒤:** 앱은 아무것도 지우지 않습니다. 탐색기·Finder 창, 바탕 화면, Dock의
  휴지통, 브라우저의 파일 올리기, 메일 첨부 어디에 놓아도 앱의 작업 패널에 작업이 생기지 않고, 앱의 목록은 폴더 감시로만
  바뀝니다. 다른 드라이브로 Shift를 누른 채 놓아 옮길 때 원본은 탐색기가 옮겨 사라지거나 그대로 남을 뿐, 앱이 지우지
  않습니다. 올리기·첨부 뒤에는 원본이 그대로입니다. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 28~30번, 33~35번)
- [ ] **macOS, 창 내용 위의 투명한 뷰가 끌기를 받는지:** Finder에서 파일을 끌어 목록의 폴더 행 위에 머물면 커서 옆
  문구("이동 → 폴더")와 행의 강조 테두리가 보이고, 놓으면 그 폴더로 옮겨집니다. 같은 창에서 클릭, 두 번 클릭, 휠,
  트랙패드 스크롤, 오른쪽 클릭 메뉴, 행·탭 끌기, 경로 입력의 I자 커서와 글자 입력이 전과 같고, 창이 전처럼(빈 곳이나
  깜박임 없이) 그려집니다. 문구와 강조가 없고 놓은 파일이 활성 패널의 폴더로 복사되면 뷰가 끌기를 받지 못하는 것이니
  macOS 판과 함께 알려 주세요. 클릭이나 휠이 창에 닿지 않으면 바로 알려 주세요. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 18번)

#### Windows

- [ ] **탐색기 → 앱:** 목록의 폴더 행, 목록의 빈 곳, 탭, 트리의 행에 각각 끌어 놓기. 키 없이는 설정대로(기본은 이동),
  Ctrl은 복사, Shift는 이동, Alt는 "링크 만들기는 아직 없습니다"와 금지 커서이고, 커서 모양·끌기 그림 아래 문구·앱의
  커서 옆 문구가 서로 맞는지. 오른쪽 버튼으로 끌어 놓으면 묻기 메뉴, 다른 드라이브(USB)는 OS 방식에서 복사, 놓은 뒤
  작업 하나와 이동의 되돌리기 알림. 머무는 곳마다 앱 안 끌기와 같은 강조 테두리가 보이고, 지나간 뒤 트리에 마우스
  표시가 남지 않는지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 10번, 17번)
- [ ] **배율과 모니터:** 배율 150%·125%인 화면과 주 모니터 왼쪽의 보조 모니터에서 강조되는 곳과 놓이는 곳이 커서
  아래의 행인지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 12번)
- [ ] **트레이에서 돌아온 창, 대화상자, 파일이 아닌 끌기:** 트레이로 숨겼다 다시 보인 창이 그대로 받는지. 대화상자(새
  폴더 이름, 확인, 충돌, 속성)나 빠른 보기가 떠 있으면 금지 커서이고 놓아도 아무 일이 없는지. 브라우저의 글자·이미지는
  끄는 내내 금지 커서인지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 13~15번)
- [ ] **탐색기에서 끈 채 자동 스크롤:** 목록·트리의 끝에 마우스를 멈추고 있으면 끝까지 굴러가고, 강조와 커서 옆 문구가
  커서 아래 행을 따라가고, 창 밖으로 나가거나 놓으면 바로 멈추는지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 16번)
- [ ] **압축 파일 안에서 끌어 오기:** 탐색기의 zip 폴더 안과 7-Zip 창에서 끌어 놓으면 복사되거나, 끌어 온 프로그램이
  임시 파일을 먼저 지웠으면 작업 완료 보고가 처리하지 못한 항목으로 알리는지(어느 쪽이었는지 적어 주세요). 압축 파일과
  다른 파일은 그대로인지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 41번)
- [ ] **앱 → 탐색기·바탕 화면:** 목록 보기의 행과 아이콘 보기의 항목에서 각각, 창 밖으로 나가는 순간 셸의 끌기 그림이
  커서를 따라가는지(그림이 없으면 적어 주세요). 같은 드라이브면 이동, 다른 드라이브면 복사, Ctrl은 복사, Shift는 이동.
  폴더 여러 개와 파일을 함께 끌어도 같은지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 28~29번)
- [ ] **끌어낸 뒤 앱 창으로 돌아오기, 그만두기:** 반대 패널에 놓으면 앱 안 끌기와 같은 동작이 한 번만 일어나는지. 돌아온
  동안 앱 창이 다시 그려지는지(그려지면 알려 주세요. 위 "알아 둘 점"을 고칩니다)와 끄는 동안의 CPU 사용량. Esc로
  그만두거나 작업 표시줄에 놓으면 아무 일도 없고, 그 뒤 클릭·끌기·다음 끌어내기가 전과 같은지.
  ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 31~32번)
- [ ] **Windows 메뉴:** 파일 하나·여러 개·폴더·빈 곳의 Shift+오른쪽 클릭과 Shift+F10, 앱 메뉴의 "더 많은 옵션 표시",
  "보내기"·"연결 프로그램" 하위 메뉴와 아이콘, 7-Zip·Git 같은 셸 확장, 메뉴의 삭제(Ctrl+Z로 되돌리기, Shift는 영구
  삭제 확인)·이름 바꾸기·잘라내기·복사·붙여넣기가 앱의 명령이 되는지, "속성" 창이 앱 앞에 뜨는지, 설정 "오른쪽 클릭에
  Windows 메뉴 바로 띄우기", 배율·왼쪽 모니터에서 메뉴의 자리, 메뉴 밖 클릭·Esc, 이름에 `;`·`&`·`%`·한글·괄호가 든
  항목. ([Windows 메뉴와 macOS 공유](docs/ux/keyboard.md#windows-메뉴와-macos-공유-ops-05) 1~11번)

#### macOS

- [ ] **Finder → 앱:** 목록의 폴더 행, 목록의 빈 곳, 탭, 트리의 행에 각각 끌어 놓기. 키 없이는 설정대로(기본은 이동),
  ⌥은 복사(+ 커서), ⌘은 이동, ⌥⌘은 "링크 만들기는 아직 없습니다"와 금지 커서. 끄는 도중 키를 누르고 떼면 마우스를
  움직이지 않아도 커서 모양과 커서 옆 문구가 함께 바뀌는지. ⇧은 동작을 바꾸지 않고 ⌃은 금지 커서인지. 다른 볼륨(USB)은
  OS 방식에서 복사, 놓은 뒤 작업 하나와 이동의 되돌리기 알림. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 19번)
- [ ] **화면과 창:** Retina 화면과 Retina가 아닌 외부 화면, 주 화면의 왼쪽과 위의 보조 화면, 창 크기를 바꾸거나 전체
  화면으로 한 뒤에도 강조되는 곳과 놓이는 곳이 커서 아래의 행인지. 메뉴 막대로 숨겼다 다시 연 창이 그대로 받는지.
  ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 21~22번)
- [ ] **대화상자, Safari의 글자, 자동 스크롤, 제목 막대, VoiceOver:** 대화상자나 빠른 보기가 떠 있으면 금지 커서이고
  끌기 그림이 Finder로 돌아가는지. Safari의 글자·링크는 끄는 내내 금지 커서인지. Finder에서 끈 채 목록·트리 끝에
  머물면 굴러가는지. 제목 막대 위에 놓으면 활성 패널의 폴더로 복사되는지. VoiceOver로 창의 목록과 버튼을 읽고 누르는
  것이 전과 같은지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 23~27번)
- [ ] **앱 → Finder·Dock의 휴지통:** 목록 보기의 행과 아이콘 보기의 항목에서 각각, 창 밖으로 나가는 순간 항목들의
  아이콘이 커서를 따라가는지. 같은 볼륨이면 이동, 다른 볼륨(USB)이면 복사, ⌥은 복사(+ 커서), ⌘은 이동인지. 휴지통에
  놓으면 Finder가 휴지통으로 옮기는지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 33~34번)
- [ ] **끌어낸 뒤 앱 창으로 돌아오기:** 반대 패널에 놓으면 앱 안 끌기와 같은 동작이 한 번만 일어나는지. 돌아온 동안
  배지와 강조가 보이고, 이동이면 커서가 이동 화살표(+가 아님), ⌥을 누르면 +인지. Esc로 그만두면 아무 일도 없는지.
  ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 36번)
- [ ] **공유…:** 항목 하나·여러 개의 "공유…"가 그 자리 아래에 공유 메뉴를 띄우고 AirDrop·메일로 보낼 수 있는지(이름에
  한글이 든 파일도 같은 파일이 첨부되는지). 빈 곳 메뉴에는 "공유…"가 없는지. ([Windows 메뉴와 macOS 공유](docs/ux/keyboard.md#windows-메뉴와-macos-공유-ops-05) 12번)

#### 두 OS 모두

- [ ] **이름에 한글·공백·`#`·`%`가 든 파일 끌어내기:** 받는 앱이 같은 이름의 파일을 받는지(macOS는 NFC와 NFD 이름
  둘 다). ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 37번)
- [ ] **끄는 동안 오른쪽 버튼·Esc:** 행을 끄는 동안 오른쪽 버튼을 누르면(Windows는 Shift를 누른 채로, 설정 "오른쪽
  클릭에 Windows 메뉴 바로 띄우기"를 켜고도) 끌기가 놓기 없이 끝나고 메뉴가 뜨지 않는지. 그 뒤 버튼을 놓고 창 밖으로
  나가 바탕 화면·탐색기·Finder 위로 가거나 반대 패널을 눌러도 아무것도 옮겨지지 않는지. 끄는 동안 Shift+F10·메뉴
  키·F10(macOS ⌃↩·⌘J)이 메뉴를 띄우지 않는지. Esc는 끌기만 그만두고 고른 항목은 그대로인지.
  ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 39~40번)
- [ ] **앱 안 끌기의 보조키와 설정:** 반대 패널의 폴더 위로 끈 채 Ctrl(macOS ⌥)을 누르고 떼면 마우스를 움직이지
  않아도 커서 옆 문구와 커서 모양이 "복사"와 "이동" 사이에서 바뀌는지. 링크 키는 금지 커서이고 놓아도 아무 일이
  없는지(macOS의 ⌃·⇧은 동작을 바꾸지 않는지). "끌어 놓기: OS 방식"(같은 드라이브는 이동, USB는 복사), "매번 묻기"
  메뉴(취소·Esc·바깥 클릭은 아무 일도 없고, 닫힌 뒤 키가 목록에 돌아오는지), 다시 실행해도 설정이 남는지.
  ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 1~5번)
- [ ] **머무르면 열기, 자동 스크롤, 되돌리기 알림:** 폴더 행·다른 탭·트리의 닫힌 폴더에 1초 머물면 열리고 그 안에 놓을
  수 있는지, 1초 전에 옮기면 열리지 않는지. 목록·트리 끝에서 끝까지 굴러가는지. 끌어서 옮기면 5초 동안 "항목 N개를
  옮겼습니다 [되돌리기]"가 뜨고 단추가 되돌리는지, 설정에서 끄면 뜨지 않는지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 6~8번)
- [ ] **Linux(X11, 개발용):** 파일 관리자의 파일을 창에 놓으면 활성 패널의 폴더로 복사되고(여러 파일은 작업 하나),
  행을 창 밖으로 끌고 나가도 OS의 끌기가 시작되지 않는지. ([끌어 놓기](docs/ux/keyboard.md#끌어-놓기-dnd) 9번, 38번)
